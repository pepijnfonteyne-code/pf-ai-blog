De focus van de afgelopen week lag niet op nieuwe modellen maar op infrastructuur: hoe agents verbinding maken met private systemen, hoe je meerdere sessies parallel beheert, en hoe je code-kwaliteit afdwingt via gestructureerde skills. Twee aankondigingen van Anthropic van 19 mei — MCP Tunnels en Self-Hosted Sandboxes — verschuiven het debat rond enterprise-adoptie van "is de AI goed genoeg?" naar "hoe isoleer je de executie correct?" Bij OpenAI landt Codex op mobile en in een beveiligde Windows-sandbox. En Addy Osmani's agent-skills library haalde #1 trending op GitHub.

Het veld beweegt op twee niveaus tegelijk: bovenaan de capability-stack komen nieuwe orchestratie- en memorypatronen online (Agent View, /goal, Dreaming), onderin de infrastructure-stack worden de loodleidingen vervangen. MCP Tunnels zijn misschien niet de meest glamoureuze aankondiging van de week, maar ze lossen een concrete blokkade op die enterprise-deployments al maanden tegenhield.

## Claude Code — MCP Tunnels en Self-Hosted Sandboxes

Aangekondigd op 19 mei op het Code with Claude-congres in Londen, in research preview en public beta respectievelijk.

**MCP Tunnels** lossen een fundamenteel infrastructuurprobleem op. Als je een Managed Agent verbindt met een interne database, een private ticketingsysteem of een intranet-API, moet die service normaal gezien publiek bereikbaar zijn of via VPN beschikbaar gesteld worden. MCP Tunnels draaien dit om: de private MCP-server maakt zelf een uitgaande versleutelde verbinding naar Anthropic-infrastructuur. De agent bereikt de service via die tunnel, zonder inbound firewallregels.

De architectuur is een split-plane design: Anthropic beheert de control plane (orchestratie, context, recovery), jij beheert de data plane (uitvoering op jouw servers). Intern gebruik je de `claude mcp tunnel` CLI-command:

```bash
# Start een MCP Tunnel voor een lokale server op poort 3000
claude mcp tunnel --port 3000 --name orion-internal
# Output: tunnel-id: mcp-tunnel-xyz123
# Gebruik dit ID in de agent-configuratie
```

In de Managed Agent config wijs je naar de tunnel-ID. De agent kan nu schrijven naar en lezen van je interne systemen zonder dat je een enkel firewall-gat hoeft te openen. Interne databases, private APIs, ticketingsystemen — ze worden allemaal MCP-tools zonder ze publiek te exposeren.

**Self-Hosted Sandboxes** (public beta) voegen de inverse controle toe: Anthropic regelt de orchestratie, maar de code-executie vindt plaats in jouw eigen cloud. Ondersteunde providers zijn Cloudflare Workers, Daytona, Modal en Vercel. Voor projecten zoals Orion betekent dit dat je een Modal-sandbox kunt configureren waarbij de agent Python-code uitvoert in jouw account — met jouw secrets, jouw network policies, jouw logging.

```yaml
# claude-agents.yaml
sandbox:
  provider: modal
  image: python:3.12-slim
  secrets:
    - name: DATABASE_URL
      source: env
  network_policy: egress-restricted
```

De combinatie van beide features maakt enterprise-grade agentic deployments realistisch zonder de security-concessies die tot nu toe onvermijdelijk waren. Wie al werkt met Remote Routines en MCP-servers voor interne tooling, kan nu rechtstreeks linken naar private infrastructure zonder de netwerkarchitectuur te herschrijven.

## Claude Code — Agent View, /goal en Dreaming

Week 20 (11–15 mei) bracht drie features die elk afzonderlijk bruikbaar zijn, maar samen het patroon van autonoom parallel werk structureel ondersteunen.

**Agent View** is wat je nodig hebt zodra je meer dan twee Claude Code-sessies parallel draait. Eén CLI-dashboard toont alle actieve sessies, inclusief hun status (loopt, geblokkeerd, voltooid) en de huidige taak. Elke sessie verschijnt als een rij met de huidige state, wat er aan gewerkt wordt, en of er input nodig is. Geen terminalsessies scrollen of tabbladen wisselen — een centrale view die het parallelle workflow-patroon dat Remote Routines propageert eindelijk ondersteuning geeft op UI-niveau.

**Het /goal-commando** verandert hoe je Claude Code instrueert voor langlopende taken. Het verschil met een gewone promptinstructie is de exit-conditie: `/goal` definiëert een eindtoestand, Claude verifieert zelf of die bereikt is en werkt autonoom door zolang dat niet zo is.

```
/goal Refactor de authentication module naar OAuth 2.0 PKCE.
Zorg dat alle bestaande tests blijven slagen en schrijf tests
voor de nieuwe flows. Commit elke logisch afgeronde stap.
```

De architectuur van /goal scheidt het werk-uitvoerende model van het evaluatieoordeel: een separate check bepaalt of het doel bereikt is, wat hallucinated completion ("klaar!") significant vermindert.

**Dreaming** is architectureel het interessantst, ook al is het nog research preview. Na het afsluiten van een sessie kijkt de agent terug op de werksessie — wat liep goed, waar werd geblokkeerd, welke aannames bleken fout — en slaat die reflectie op als experiential memory. De volgende sessie begint met die kennis beschikbaar. Harvey, een legal AI platform, rapporteerde een 6x hogere task completion rate na implementatie van Dreaming voor het consolideren van agent-memory over juridische onderzoekssessies.

De lus die dit implementeert is: uitvoering → reflectie → aanpassing. In traditionele systemen programmeer je die lus handmatig. Dreaming probeert het als emergent property te maken. Voor langlopende Orion-projecten waarbij de agent over meerdere sessies dezelfde codebase bewerkt, is het meest directe voordeel eenvoudig: de agent vergeet niet meer wat afgelopen week niet werkte.

Multiagent Orchestratie — ook onderdeel van dezelfde release — laat een lead agent taken opsplitsen naar specialist-subagents met eigen model, prompt en toolset. De specialists werken parallel op een gedeeld filesystem en leveren terug aan de lead agent. De limieten: tot 20 distinct subagent types, tot 25 parallel threads per orchestratie.

## OpenAI — Codex op mobile en in een beveiligde Windows-sandbox

OpenAI voegde Codex toe aan de ChatGPT-app (iOS en Android) voor alle plannen inclusief Free en Go in ondersteunde regio's. In de praktijk: je zet 's ochtends een Codex-taak in gang, doet andere dingen, en keurt vanuit de app een buildstap goed als de agent om input vraagt. Het is geen volledige mobile IDE — de sessies draaien remote, mobile is het beheerscherm. Huidige beperking: mobile pairing vereist voorlopig een macOS host, Windows mobile pairing staat als "coming soon".

De **Codex Windows Sandbox** brengt stricter sandbox-gedrag: firewall-backed network blocking, dedicated setup en runner binaries, en tightere file-write controls. Het is een iteratie op de March 2026 Windows launch, waarbij de focus lag op enforcement zonder gewone development-workflows te breken. Enterprise features die tegelijk uitkwamen: HIPAA-ondersteuning, remote SSH, access tokens voor ChatGPT Enterprise workspaces en een Dell Technologies partnerschap voor on-premises Codex.

De parallellen met Anthropic's Self-Hosted Sandboxes zijn opvallend. Beide bedrijven lossen hetzelfde enterprise-dilemma op: agents zijn krachtig, maar IT-afdelingen willen executie-omgevingen binnen hun security perimeter houden. Het verschil is de insteek: OpenAI legt nadruk op compliance (HIPAA, on-prem), Anthropic op provider-keuze en infrastructure-portabiliteit (Modal, Cloudflare, Vercel).

## Open Source Tools — agent-skills v0.6.0

Addy Osmani (Google Chrome-team) bracht v0.6.0 uit van [agent-skills](https://github.com/addyosmani/agent-skills) — een collectie van 23 gestructureerde Markdown-workflows voor AI coding agents. De week van 13 mei stond het #1 trending op GitHub.

Het centrale idee: agents kiezen standaard de kortste weg. Een gestructureerde skill dwingt een kwalitatief betere route af. De skills zijn plain Markdown — compatibel met elk systeem dat systeemprompts of instructiebestanden accepteert (Claude Code, GitHub Copilot, Cursor). Zeven slash-commands activeren automatisch de juiste workflow:

```
/spec      → spec-first development (schrijft eerst spec, dan code)
/review    → code review met security-checks en severity-annotaties
/ship      → geautomatiseerde CI/CD-workflow checklist
/ddd       → doubt-driven development (agent stelt clarifying questions)
```

`/ddd` is het patroon dat minder voor de hand ligt maar het meest waardevol is bij early-stage features. De agent stelt actief clarifying questions voordat hij begint te bouwen. In projecten met vage of evoluerende requirements — wat bij early-stage Orion-features de norm is — voorkomt dit de standaardfout waarbij de agent vrolijk de verkeerde oplossing bouwt.

Installatie via de Claude Code marketplace of handmatig door de `.claude/skills/` directory te vullen. Integreren in `CLAUDE.md` als kwaliteitslaag maakt ze actief voor alle projecten in de workspace:

```markdown
<!-- CLAUDE.md -->
## Coding Standards
Use agent-skills for all development workflows:
- Always run /spec before implementing new features
- Use /review before committing non-trivial changes
- Apply /ddd when requirements are ambiguous
```

## Tot slot

Wat opvalt aan de aankondigingen van deze week is dat de architecturale discussie verschuift van "wat kan een model" naar "waar draait de code en wie controleert de omgeving". MCP Tunnels en Self-Hosted Sandboxes zijn niet de meest glamoureuze features, maar ze adresseren precies de vragen die enterprise-teams stellen voordat ze iets in productie zetten. Dat Anthropic dit nu uitbrengt terwijl ook OpenAI met een beveiligde Windows-sandbox komt, suggereert dat de markt hier agressief om vroeg — en dat dit het volgende harde vereiste wordt naast de capability-discussie.

De vraag die blijft hangen: als agents straks via Dreaming hun eigen sessiehistory doorkijken, via /goal autonoom doorwerken tot een doel bereikt is, en via multiagent orchestratie 25 parallelle threads coördineren op jouw private infrastructure — op welk punt is menselijk toezicht nog een onderdeel van het systeem, en op welk punt wordt het een procedueel checkbox dat niemand echt leest?
