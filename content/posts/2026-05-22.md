VS Code 1.121, uitgebracht op 20 mei, plaatst Claude Code Remote Agents direct in de IDE: agentic sessies starten, monitoren en aansturen zonder een lokale terminal open te houden. Een dag later kondigt Google een breaking change aan in de Gemini Interactions API — effectieve datum 26 mei — die elke client die de Interactions API gebruikt vóór maandag moet migreren of ziet breken. Twee bewegingen die los van elkaar staan, maar allebei de verschuiving van capability-uitbreiding naar infrastructuurconsolidatie illustreren.

De week bevat ook twee tooling-releases die onder de radar bleven maar de agent-stack interessant opschuiven: AWS brengt zijn MCP Server naar general availability met native IAM-guardrails, en Bernstein duikt op als CLI-orchestrator voor 40+ coding agents met auditlogging en git-worktree-isolatie. Simon Willison publiceerde ondertussen een reflectie die zijn eigen praktijk als lens gebruikt om het onderscheid tussen "vibe coding" en "agentic engineering" te herformuleren — en vast te stellen dat dat onderscheid in de praktijk aan het verdwijnen is.

## Claude Code — VS Code 1.121 en Remote Agents integratie

VS Code 1.121 bevat de meest significante Claude Code UI-integratie tot nu toe: Remote Agents kunnen rechtstreeks vanuit de editor gestart, gemonitord en aangestuurd worden. Dit is de gebruikslaag bovenop de Anthropic Managed Agents API, die eerder dit jaar in preview ging.

Het Remote Agents paneel in de Activity Bar laat je een Claude Code-sessie starten die draait in een gehoste Anthropic-omgeving — niet op jouw machine. De sessie heeft toegang tot dezelfde MCP-server configuratie die je lokaal gebruikt via de MCP Tunnels die vorige week in preview gingen, maar draait asynchroon. VS Code sluiten, agent werkt door.

```yaml
# .claude/remote-agent.yaml
agent:
  model: claude-opus-4-7
  mcp_servers:
    - tunnel_id: mcp-tunnel-xyz123  # interne DB
    - tunnel_id: mcp-tunnel-abc456  # interne API
  sandbox:
    provider: modal
    image: python:3.12-slim
  on_complete:
    webhook: https://hooks.orion.internal/agent-done
```

De voornaamste winst ten opzichte van lokale sessies: geen open terminal-venster, geen lokale compute, en de `on_complete` webhook triggert downstream pipelines in Orion zodra de agent klaar is. De ingebouwde Mermaid-preview in VS Code 1.121 is een nuttige bonus voor agents die architectuurdiagrammen genereren als output.

Voor CI auto-fix is dit de interessante use case: een CI-pipeline triggert een Remote Agent-sessie via de Managed Agents API na een falende test, de agent analyseert de fout en opent een PR met de fix. Geen developer in de loop. De sandbox-architectuur per sessie — Anthropic beheert de control plane, jij de data plane via Self-Hosted Sandboxes — maakt dat de agent schrijfrechten krijgt op jouw codebase zonder dat die code buiten jouw cloud-omgeving gaat.

## Gemini — Interactions API breaking change op 26 mei

Dit vereist actie voor maandag. Google heeft een breaking change aangekondigd in de Gemini Interactions API met effectieve datum 26 mei. Alle clients die de Interactions API gebruiken moeten gemigreerd zijn voor dan, anders breken ze.

Twee concrete wijzigingen:

**1. Schema-rename: `outputs` → `steps`**

```python
# VOOR (breekt na 26 mei)
response = gemini.interact(prompt)
for output in response.outputs:
    print(output.text)

# NA
response = gemini.interact(prompt)
for step in response.steps:
    print(step.text)
```

**2. Output format configuratie**

```python
# VOOR
gemini.interact(prompt, output_format="markdown")

# NA
gemini.interact(prompt, config=InteractConfig(format="markdown"))
```

De wijziging raakt elke codebase die direct met de Gemini Interactions API werkt — inclusief Python-wrappers die op de `outputs`-key leunen. Een snelle manier om te inventariseren wat geraakt wordt:

```bash
grep -r "\.outputs" . --include="*.py" | grep -i gemini
grep -r "output_format" . --include="*.py" | grep -i gemini
```

Naast de breaking change lanceerde Google op I/O ook de Gemini Managed Agents API in public preview: stateful agent-sessies in geïsoleerde Google-hosted Linux-sandboxen, vergelijkbaar met Anthropic's Self-Hosted Sandboxes qua concept maar gehost bij Google. Tegelijk introduceerde Google event-driven webhooks als vervanging voor polling-loops in de Batch API — direct bruikbaar voor async agent-workflows. Gemini Spark, de altijd-actieve proactieve agent die op Google I/O werd gepresenteerd, gebruikt MCP voor third-party tool connectivity met 30+ connectoren (Adobe, Dropbox, Uber). Dat is architectureel relevant: een MCP-server die je nu voor Claude Code bouwt is potentieel ook inzetbaar als Spark-connector.

## Open Source Tools — AWS MCP Server GA en Bernstein orchestrator

Twee tooling-releases die elk productie-relevante problemen oplossen.

**AWS MCP Server** is vanaf 6 mei generally available. De kern: een managed MCP-server die AI coding agents veilige toegang geeft tot alle AWS APIs, met IAM-guardrails, CloudWatch metrics en CloudTrail logging ingebouwd. De server voert Python-scripts uit in een sandboxed omgeving zonder toegang tot het lokale filesystem. Elke AWS API-aanroep is een tool-call die via CloudTrail wordt gelogd.

```json
{
  "mcpServers": {
    "aws": {
      "command": "aws-mcp-server",
      "args": ["--region", "eu-west-1"],
      "env": {
        "AWS_PROFILE": "orion-prod"
      }
    }
  }
}
```

Resultaat: Claude Code agents kunnen S3-buckets aanmaken, Lambda-functies deployen of RDS-queries uitvoeren via tool-calls, met volledige IAM-controle over wat toegestaan is. Geen API keys in prompts, geen overbrede rechten, audit trail ingebakken.

**Bernstein** is een Python-orchestrator (Apache-2.0) die parallel opereert op 40+ CLI coding agents: Claude Code, Codex, Gemini CLI, Cursor, Aider. De designkeuze die opvalt: één LLM planning-call splitst een grotere taak op in parallel uitvoerbare subtaken, elk geïsoleerd in een eigen git-worktree. Per subtaak draait één agent. Een quality gate evalueert het resultaat voor merge. HMAC-chaining zorgt dat de audit trail van alle agent-acties onweerlegbaar is — elke stap is cryptografisch gekoppeld aan de vorige.

```python
from bernstein import Orchestrator

orch = Orchestrator(
    planner_model="claude-opus-4-7",
    agents=["claude-code", "gemini-cli"],
    quality_gate="strict"
)

result = orch.run(
    task="Refactor authentication module naar OAuth 2.0 PKCE",
    repo=".",
    parallel=True
)
```

De git-worktree-isolatie is de technisch interessante keuze: elke agent-run werkt op een eigen branch-kopie, wat merge-conflicten bij parallelle runs structureel vermijdt. De combinatie van Bernstein als orchestratielaag met de AWS MCP Server als tooling-backend is een interessante richting voor multi-agent setups in Orion: parallelle agents, gecontroleerde AWS-toegang, onweerlegbare audit trail.

## AI Builders — Simon Willison: vibe coding en agentic engineering vloeien samen

Simon Willison publiceerde op 6 mei een reflectie die begint als blog post en uitmondt in een taxonomieprobleem. Het onderscheid dat hij zelf helpt populariseren — "vibe coding" (snel prototypen, AI output overnemen zonder volledig begrip) versus "agentic engineering" (methodisch AI gebruiken als tool onder je eigen controle) — begint in zijn eigen praktijk te verdwijnen.

De aanleiding: bij het live bloggen van Code with Claude 2026 bouwde hij features voor zijn website terwijl hij verslag deed — Claude Code for Web, snel, weinig oversight, code grotendeels overnemen. Klassiek vibe coding. Maar de features werkten, de code was achteraf begrijpelijk, en zijn review leverde geen noemenswaardige problemen op.

Zijn observatie: naarmate de modellen sterker worden en de tooling (MCP, sandboxes, Agent View) de feedback loops verkort, verschuift de grens waar verantwoord autonoom werken overgaat in roekeloos. De categorie "agentic engineering" dreigt de strekking van alles te absorberen dat werkt — wat het onderscheid betekenisloos maakt als designkeuze, maar tegelijk de vraag stelt hoe je verantwoordelijkheid organiseert in een team dat Claude Code actief inzet.

Zijn Google I/O coverage van 20 mei is de moeite waard als referentie — specifiek zijn nuancering dat hij terughoudend is over features die nog niet GA zijn, wat zijn analyse betrouwbaarder maakt als filter voor wat nu productie-ready is versus wat over drie maanden pas relevant wordt.

## Tot slot

Wat deze week markeert is de volwassenwording van agentic infra. De modellen zijn sterk genoeg — het debat is nu hoe je executie isoleert, wie toegang heeft tot welke systemen, en hoe je agent-output verifieert en auditeert. AWS MCP Server GA, Remote Agents in VS Code, Bernstein's git-worktree-isolatie: het zijn loodleidingen-upgrades, geen capability-sprongen.

De Gemini breaking change van 26 mei is het meest urgente punt. Daarna loont het om Bernstein te bekijken als orchestratielaag voor parallelle agent-sessies in Orion — de combinatie met de AWS MCP Server en de audit-logging die erbij zit tekent een production-ready multi-agent setup die een paar maanden geleden nog handmatig assembleerwerk was.
