## Claude Code — Claude Security en het /goal command

**Claude Security: automated vulnerability scanning in public beta**

Claude Security ging op 22 mei 2026 in public beta voor Claude Enterprise-klanten. Het systeem gebruikt Opus 4.7 om codebases te analyseren via twee technieken die elkaar aanvullen: *dataflow-analyse* en *cross-file interactie-tracing*.

Dataflow-analyse volgt variabelen en data-transformaties door de code om te detecteren waar ongesanitiseerde input een gevoelig sink bereikt — een klassieke source-to-sink analyse, maar dan met de contextuele redenering van een groot taalmodel. Cross-file interactie-tracing gaat verder: het model begrijpt hoe functies en componenten over meerdere bestanden samenwerken, wat patronen zichtbaar maakt die statische analyse-tools missen omdat ze niet verder kijken dan de scope van één bestand. Een SQL-injection via een helper-functie die drie lagen diep wordt aangeroepen vanuit een API-endpoint — dat is precies het type kwetsbaarheid dat dit oppikt waar een linter het niet ziet.

Na detectie genereert het systeem gerichte patches die voor review worden aangeboden. Geen automatisch committen; een mens blijft verantwoordelijk voor de definitieve beslissing. In de eerste drie weken na intern gebruik werden al meer dan 2.100 kwetsbaarheden gepatcht via dit systeem.

De workflow integreert met bestaande security-tooling: CrowdStrike, Microsoft Security, Palo Alto Networks, SentinelOne, TrendAI en Wiz hebben live integraties. Je kunt scheduled scans instellen of targeted scans draaien op specifieke modules. Triaged findings en audit-systeemintegratie zijn beschikbaar.

Het interessantste toepassingspatroon is de end-to-end loop: Claude Code bouwt een feature branch, Claude Security draait een scan op de nieuwe code, en de bevindingen komen als gestructureerde input terug in een review-PR — zonder externe tooling voor de scanfase.

```bash
# Targeted scan op een kritieke module
claude security scan \
  --target src/auth/ \
  --severity high,critical \
  --output findings.json

# Patches genereren als draft PR
claude security patch \
  --findings findings.json \
  --branch security/$(date +%Y%m%d) \
  --draft-pr
```

Voor projecten met veel externe dependencies of een snelgroeiende codebase zonder dedicated security-team is dit relevant. De combinatie van cross-file tracing en integratie met bestaande SIEM-systemen maakt het bruikbaar als laag bovenop wat je al hebt, niet als vervanging.

**Week 20: /goal command en 1M context in Fast mode**

Claude Code Week 20 bracht ook het `/goal` command. Je stelt een conditie in en Claude werkt autonoom door tot die conditie geldt — zonder manuele herstart of bijsturing per turn.

```bash
# Claude werkt door tot alle unit tests slagen
/goal "alle unit tests in src/payments/ slagen"

# Of tot een specifieke bestandsstatus bereikt is
/goal "CHANGELOG.md bevat een entry voor versie 2.4.0"
```

Dit is de functionele tegenhanger van Agent View: Agent View geeft je overzicht en controle over parallelle sessies, `/goal` geeft een individuele sessie een expliciete exit-conditie zonder dat je erbij hoeft te blijven. Fast mode draait nu standaard op Opus 4.7 met 1M context window — relevant voor grote codebase-analyses die eerder moesten splitsen over meerdere sessies of noodgedwongen context moesten droppen.

## Gemini — 3.5 Flash: 83.6% op MCP Atlas

Google lanceerde Gemini 3.5 Flash op Google I/O op 19 mei 2026. De eerste concrete benchmarkcijfers zijn inmiddels beschikbaar en geven een aardig beeld van waar het model staat op agentic use cases.

Drie relevante benchmarks:

| Benchmark | Gemini 3.5 Flash | Wat het meet |
|-----------|------------------|--------------|
| Terminal-Bench 2.1 | 76.2% | Coding in terminal, autonome taakafwerking |
| GDPval-AA | 1656 Elo | Agentic real-world tasks |
| MCP Atlas | 83.6% | Tool-use reliability op schaal |

De MCP Atlas-score is het meest interessant voor agentic pipelines. MCP Atlas test hoe betrouwbaar een model tools aanroept over een groot aantal calls — niet alleen of het de juiste tool kiest, maar of het dat consistent doet onder variabele omstandigheden met complexe tool-schemas. 83.6% op schaal is sterk; GPT-5.5 scoort lager op dezelfde benchmark.

Het model is ook significant sneller: 4x hogere output tokens per seconde dan andere frontier modellen. Voor bulk-verwerkingsscenario's — grote codebases scannen, veel documenten verwerken, meerdere parallelle agentic calls — maakt dat een substantieel verschil in kosten en doorlooptijd.

Een concrete vergelijking waard: als je nu Opus 4.7 inzet als backbone voor MCP-server integrations waar latency kritisch is, is Gemini 3.5 Flash interessant om te benchmarken op diezelfde use case. De MCP Atlas-score suggereert dat tool-use reliability niet de bottleneck zal zijn.

```python
# Gemini 3.5 Flash testen met je bestaande MCP-tool schemas
import google.generativeai as genai

genai.configure(api_key="YOUR_API_KEY")
model = genai.GenerativeModel('gemini-3.5-flash')

# MCP-tools als function declarations meegeven
response = model.generate_content(
    contents="Voer deze agentic taak uit...",
    tools=your_mcp_tool_declarations,
    generation_config=genai.GenerationConfig(temperature=0)
)
```

Gemini 3.5 Pro is intern al in gebruik bij Google en staat gepland voor juni 2026. De Flash-variant is nu beschikbaar via de Gemini API, AI Mode in Google Search en enterprise platforms.

## AI Builders — Simon Willison's live blog van Code w/ Claude 2026

Simon Willison publiceerde op 6 mei 2026 een uitgebreide live blog van het Anthropic developer event "Code w/ Claude 2026". Het is de moeite waard om te lezen nu de features die er gedemonstreerd werden — Agent View, /goal, de plugin-architectuur — de afgelopen weken daadwerkelijk zijn uitgerold.

Willison's waarde als schrijver over AI-tools is zijn consequente onderscheid tussen gedemonstreerd gedrag en daadwerkelijk gedrag in productie. Zijn annotaties bij de Claude Code demos bevatten specifieke observaties over de "kloof tussen showcase en dagelijks gebruik": features werken zoals gedemonstreerd, maar vereisen meer context-beheer dan de demos suggereren. Zijn observatie dat de plugin/skill-architectuur het interessantste nieuwe paradigma is — niet omdat het fundamenteel anders is dan vorige agentic frameworks, maar omdat het de complexiteit van agent-compositie neerlegt op een niveau dat minder abstractie vereist dan alternatives zoals LangGraph of CrewAI.

Zijn live blog heeft ook praktisch nut als index: het bundelt technische demos, hands-on inzichten en links naar relevante commits en release notes voor de features uit de eerste mei-week. Als je Agent View of /goal gaat evalueren voor je eigen workflow, is Willison's kritische blik op de "real-world limitations" een nuttige kalibratie naast de officiële documentatie.

De bredere observatie uit zijn blog sluit aan bij wat we vandaag ook in Claude Security zien: het onderscheid tussen "vibe coding" en "agentic engineering" is aan het vervagen — niet omdat agentic engineering makkelijker wordt, maar omdat de tooling vibe-coding steeds meer elimineert als snelkoppeling. Automatisering verplaatst de menselijke taak van uitvoering naar beoordeling. Dat is een verschuiving in vaardigheidsprofiel, niet in verantwoordelijkheid.

## Tot slot

Claude Security en het `/goal` command zijn de meest tastbare uitbreiding van de Claude Code-workflow deze week. Ze adresseren twee verschillende problemen — security debt en autonoom doorwerken — maar delen dezelfde onderliggende logica: de menselijke rol verschuift naar reviewen en goedkeuren in plaats van uitvoeren. De vraag die blijft hangen is hoe die reviewrol zich ontwikkelt als de hoeveelheid gegenereerd werk de reviewcapaciteit overstijgt — een probleem dat Claude Security's triaged findings en patch-suggesties deels adresseert, maar niet volledig oplost.

De Gemini 3.5 Flash benchmarks op MCP Atlas geven voor het eerst concrete getallen op tool-use reliability op schaal. Of die cijfers standhouden in productieworkflows is te beoordelen na directe vergelijking met je eigen MCP-server configuraties. Maar 83.6% maakt het model serieus genoeg om te testen als alternatieve backbone voor MCP-heavy pipelines — zeker als throughput een bottleneck is.
