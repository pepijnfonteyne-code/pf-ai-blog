De afgelopen week verschoof de focus in het agentic AI-ecosysteem van capability naar continuïteit: hoe laat je een agent doorgaan als je niet kijkt, hoe geef je hem persistent context over sessiegrenzen heen, en hoe integreer je hem in de review-loop van een bestaand team zonder custom glue code te schrijven? Vier updates geven elk een ander antwoord op die vraag.

Het interessante is dat ze uit vier verschillende hoeken komen — Anthropic, OpenAI, Alibaba en de open source tooling-wereld — en toch allemaal dezelfde richting opgaan: agents die persistent zijn, protocolcompatibel zijn, en integreren via standaard API-surfaces in plaats van bespoke integraties. Dat is een architectureel signaal de moeite waard om te volgen.

## Claude Code — /code-review als standalone CI-pipeline

Claude Code v2.1.147 hernoemt `/simplify` naar `/code-review` en voegt twee eigenschappen toe die het fundamenteel anders maken dan een lokale review-helper: een instelbaar effort-niveau en de mogelijkheid om bevindingen als inline GitHub PR-comments te posten.

```bash
# Lokaal gebruik met hoog effort-niveau
/code-review high

# Als onderdeel van een CI-pipeline: pusht als inline PR-review
/code-review high --comment
```

Het `--comment` flag stuurt de bevindingen via de GitHub API als een formele PR-review — niet als een losse opmerking, maar als een review-object met inline commentaar op specifieke regels. Dat maakt Claude Code inzetbaar als autonoom reviewstadium vóór human review, zonder dat je een aparte code review tool, een webhook-integratie of een custom GitHub Action script nodig hebt.

```yaml
# Minimale GitHub Actions job voor review als PR-comment
- name: Claude Code Review
  run: claude /code-review high --comment
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

De tweede toevoeging in deze release zijn **gepinde achtergrond-sessies** via `Ctrl+T` in `claude agents`. Sessies blijven nu actief bij inactiviteit — een praktische fix voor langlopende agent-loops die eerder onduidelijk termineerden bij een idle timeout. In combinatie met Agent View kun je meerdere parallelle sessies beheren vanuit één terminal: een review-agent en een fix-agent naast elkaar, zonder dat je constant moet bijhouden welke sessie nog actief is.

v2.1.148 — uitgebracht een dag later — repareert een regressie waarbij alle Bash-commando's exit code 127 teruggaven. Als je op 2.1.147 vastliep met mysterieuze tool-failures: direct updaten.

## OpenAI — Codex Goal Mode stabiel en Appshots-context

Codex Goal Mode verlaat de experimentele fase. Het concept is niet nieuw, maar de stabilisatie is relevant voor wie dit serieus wil inzetten: Goal Mode laat je een doel toewijzen dat Codex bijhoudt over meerdere sessies en token-budget-resets heen, totdat het bereikt is. De voortgang wordt opgeslagen in dedicated persistent storage buiten de actieve conversation — fundamenteel anders dan stateless turn-by-turn interactie.

```bash
# CLI update naar versie met Goal Mode stable
npm install -g @openai/codex@0.128.0
```

Dit is functioneel equivalent aan Claude Code's `/goal` command, maar de implementatiekeuze is de moeite van het vergelijken waard: waar Claude Code `/goal` als een commando-instructie behandelt die de agent zelf in zijn context bijhoudt, heeft Codex's Goal Mode een externe state store. In de praktijk betekent dat robuuster herstel na crashes of sessieverliezen.

**Appshots** (macOS, app v26.519+) is de architectureel interessantere toevoeging. Een dubbele Command-druk injecteert een screenshot én de volledige tekst van het frontste venster in de actieve Codex-thread via accessibility APIs — automatische visuele contextinjectie zonder dat je handmatig een screenshot maakt of een MCP-server schrijft die scherminhoud leest.

**Locked Machine mode** sluit het drieluik: Codex kan autonoom doorgaan op een vergrendelde Mac, met remote start via de mobiele app. Dat positioneert Codex als een achtergrond-agent die je buiten je normale werksessie laat doordraaien — dezelfde niche als Remote Routines, maar dan in het OpenAI-ecosysteem.

*Bron: [OpenAI Codex Changelog](https://developers.openai.com/codex/changelog)*

## Hermes / Open Source — Qwen3.7-Max: drop-in Anthropic API met 1M context

Alibaba lanceerde Qwen3.7-Max als een agent-first redeneermodel met twee eigenschappen die het direct inzetbaar maken zonder dat je je bestaande tooling hoeft aan te passen: **native ondersteuning voor het Anthropic API-protocol** en een contextvenster van 1 miljoen tokens.

Op de benchmarks die relevant zijn voor agentic codetaken:
- **SWE-Pro**: 60,6
- **Terminal-Bench 2.0**: 69,7
- **Zelfstandige agent-taken tot 35 uur**: ondersteund

```python
# Via OpenRouter als drop-in vervanging voor Claude in Anthropic SDK-code
import anthropic

client = anthropic.Anthropic(
    base_url="https://openrouter.ai/api/v1",
    api_key="<OPENROUTER_KEY>",
)

message = client.messages.create(
    model="qwen/qwen3.7-max",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Refactor this function for readability."}]
)
```

De chain-of-thought redenering wordt intern gegenereerd vóór het definitieve antwoord — vergelijkbaar met Claude's extended thinking, maar niet afzonderlijk gefactureerd. Beschikbaar via DashScope API ($2,50/$7,50 per 1M tokens input/output) en OpenRouter.

Het belangrijkste voorbehoud: gesloten gewichten. Qwen3.7-Max is alleen als API beschikbaar. Een open-weight variant (27B/35B) is aangekondigd voor juni-juli 2026 — pas dan wordt lokale deployment of fine-tuning een optie. Voor nu is het interessant als benchmark van je eigen Anthropic SDK-setup: swap de base URL, run dezelfde prompts, vergelijk kwaliteit versus kostprijs voor batch-werklasten.

## Open Source Tools — WordPress 7.0 MCP Adapter en LangGraph cron support

Twee updates die hetzelfde patroon volgen: bestaande systemen bruikbaar maken als MCP-providers of gestructureerde agent-backends zonder bespoke integraties.

**WordPress 7.0 'Armstrong'** (20 mei) introduceert een officieel MCP Adapter-pakket dat de WordPress Abilities API omzet naar MCP-tools. Elke WordPress-installatie wordt zo een MCP-server: content publiceren, pagina's beheren en metadata aanpassen via standaard MCP protocol, zonder dat je een custom REST API client of webhook-logica schrijft.

```bash
# WordPress MCP Adapter via Composer
composer require automattic/wordpress-mcp-adapter

# Of als WP-CLI plugin install
wp plugin install wordpress-mcp-adapter --activate
```

Eens geïnstalleerd, roept Claude WordPress-functies aan als gewone MCP tool calls — hetzelfde integratiepatroon als met elke andere MCP-server. Voor agent-workflows waarbij content-publicatie een stap is (denk: research agent die een draft publiceert, of een rapportage-agent die wekelijks een update post), is dat een directe shortcut.

**LangGraph 1.2.1** (21-22 mei) voegt **cron-filter support** toe in de SDK voor geplande agent runs — relevant voor wie een agent op een schema wil laten draaien zonder een externe scheduler te schrijven of een cron-job te configureren:

```python
from langgraph_sdk import get_client

client = get_client()
await client.crons.create(
    assistant_id="daily-report-agent",
    schedule="0 6 * * *",  # elke dag om 6:00 UTC
    input={"task": "generate_daily_summary"}
)
```

De patch repareert ook tool-results handling in v3 messages en voegt `before_builtins` opt-in toe voor stream transformers — kleine fixes, maar de cron-support is de feature die de stap naar autonome, geplande agent-operaties vereenvoudigt.

*Bronnen: [WordPress.org News](https://wordpress.org/news/2026/05/armstrong/) — [LangGraph GitHub Releases](https://github.com/langchain-ai/langgraph/releases)*

## Tot slot

Wat opvalt is dat alle vier de updates hierboven gaan over continuïteit en integratie, niet over rauwe capability. De vraag is niet meer "kan een AI-agent dit aan?" maar "hoe laat je hem doorgaan als je niet kijkt, en hoe geef je hem toegang tot je bestaande stack?"

De protocollaire convergentie daarin is opmerkelijk: Qwen3.7-Max implementeert het Anthropic API-protocol, WordPress publiceert een MCP Adapter, en LangGraph voegt scheduler-primitieven toe die het patroon van planningtools en agent-orkestratie samenbrengen. Infrastructuur standaardiseert sneller dan de agents zelf volwassen worden — en dat is waarschijnlijk precies wat nodig is.
