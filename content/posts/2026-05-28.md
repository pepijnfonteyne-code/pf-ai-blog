Binnen acht dagen voegden drie van de grootste AI-providers native MCP-support toe aan hun productie-stack. Dat is minder een toeval dan een bevestiging: het protocol is aangeslagen. Tegelijkertijd verfijnt de Claude Code-stack zijn positie met twee releases die focussen op enterprise-governance en sessie-robuustheid. En OpenAI lost een architectureel probleem op dat iedereen met een remote agent-setup kent: hoe stuur je een agent die achter NAT zit, zonder je machine aan het publieke internet bloot te stellen?

De drie bewegingen zijn los van elkaar, maar samen schetsen ze een duidelijk richtinggevoel: agentic AI verschuift van experimenteel naar beheerbaar. Governance, observability en veilige remote control zijn geen afterthoughts meer — ze zitten ingebakken in de tools.

## Claude Code — Enterprise MCP-config en /usage per categorie

Twee recente releases (v2.1.148 en v2.1.150) voegen features toe die relevant zijn voor iedereen die MCP serieus inzet in een team-context.

**`allowAllClaudeAiMcps` — één instelling voor centrale MCP-registratie**

In een enterprise-setup kon je MCP-servers tot nu toe alleen configureren via `managed-mcp.json`. Dat bestand bepaalt welke servers beschikbaar zijn voor alle medewerkers in de organisatie. Het nadeel: MCP-connectors die geconfigureerd zijn via de Claude.ai-interface waren niet automatisch beschikbaar in Claude Code — je moest ze afzonderlijk herregistreren in `managed-mcp.json`.

v2.1.150 lost dit op met één nieuwe instelling:

```json
// .claude/settings.json (enterprise managed policy)
{
  "allowAllClaudeAiMcps": true
}
```

Met deze instelling op `true` worden alle MCP-connectors die geconfigureerd zijn in Claude.ai automatisch beschikbaar naast de servers in `managed-mcp.json`. Als jullie connector-registry al in Claude.ai leeft — meerdere team-leden onderhouden die daar — hoef je die niet meer te dupliceren in JSON-bestanden per project.

Valideer eerst op een test-org: zo zie je precies welke connectors beschikbaar komen vóór je naar productie uitrolt. Bij een Orion-setup is het de moeite waard de server-lijst te auditen op duplicaten en conflicterende tool-namen.

**`/usage` — per categorie**

De `/usage`-opdracht toonde tot nu toe een aggregaat van je limieten. Vanaf v2.1.150 krijg je een uitsplitsing per categorie:

```
/usage
├── Skills          342k tokens  (38%)
├── Subagents       289k tokens  (32%)
├── Plugins          198k tokens  (22%)
└── MCP Servers
    ├── orion-connector   67k tokens  ( 7%)
    └── filesystem         12k tokens  ( 1%)
```

Als je meerdere MCP-servers in een workflow draait, zie je nu exact welke server het meeste token-budget opslokt. Dat is de eerste stap naar cost-routing: dure calls doorsturen naar goedkopere modellen of caching inzetten voor repetitieve tool-responses.

**Gepinde sessies overleven pakketupdates**

v2.1.148 pakt een ander irritatiepunt aan: gepinde achtergrond-sessies (Ctrl+T in `claude agents`) gaan niet meer verloren bij een auto-update van Claude Code. De daemon implementeert nu een twee-traps lifecycle. Bij geheugendruk worden niet-gepinde sessies eerst vrijgegeven. Gepinde sessies worden in-place herstart via een state-snapshot/restore-mechanisme — de Claude Code-versie wordt bijgewerkt zonder de sessiestatus te verliezen.

```bash
# Start een achtergrond-sessie
claude agents   # → Ctrl+T op de sessie die je wil pinnen
```

Bruikbaar voor langlopende CI-loops of monitoring-agents in Orion: de sessie overleeft nachtelijke updates zonder handmatig herstarten.

## OpenAI — Codex op mobiel via secure relay

Op 14 mei lanceerde OpenAI Codex binnen de ChatGPT-app op iOS en Android. De feature zelf — je coding agent sturen vanuit je telefoon — is handig. De architectuur erachter is het interessantst.

Het probleem dat OpenAI oploste: hoe bereik je een desktop-agent die achter NAT zit, zonder die machine direct aan het internet bloot te stellen? Het antwoord is een **secure relay-laag**. De host-machine maakt een uitgaande verbinding met de relay. Die relay fungeert als bi-directioneel kanaal: opdrachten en goedkeuringen stromen van je telefoon naar de machine, terminal output, diffs, screenshots en test-resultaten stromen terug.

```
[Telefoon]  ←→  [OpenAI Relay]  ←→  [Desktop Codex Agent]
                                          ↓
                                   [Lokale bestanden]
                                   [Credentials]
                                   [Tool executie]
```

Files, credentials en permissies blijven volledig op de host-machine. De telefoon heeft geen directe toegang tot het bestandssysteem. Op de phone wissel je tussen threads, keur je tool-calls goed en stuur je model-keuze bij — executie blijft volledig op de desktop.

Het onderliggende model is `codex-1`, een o3-variant getraind op real-world coding tasks via reinforcement learning. Momenteel ondersteunt de mobiel-naar-desktop-koppeling macOS; Windows-support is aangekondigd.

Deze relay-architectuur is een bruikbaar patroon voor eigen agent-pipelines. Als je een Remote Routines setup hebt waarbij een agent op een server draait en je die wil aansturen zonder SSH-tunnels of port-forwarding, is de relay-aanpak (uitgaande WebSocket, bi-directioneel over één verbinding) de schonere oplossing ten opzichte van inbound firewall-uitzonderingen.

## Open Source Tools — MCP bereikt universele provider-adoptie

Drie grote AI-providers voegden MCP-support toe binnen acht dagen:

| Provider | Datum | Feature |
|----------|-------|---------|
| OpenAI | 21 mei | MCP in Responses API en Agents SDK |
| Anthropic | 22 mei | Enterprise MCP-connectors in Claude Code |
| Mistral | 27 mei | MCP Connectors in Studio, public preview |

Mistral's implementatie focust op governance. Via de Studio API zijn MCP-server endpoints registreerbaar als native tools, met een ingebouwde approval-workflow per tool-call:

```python
from mistralai import Mistral

client = Mistral(api_key="...")

# MCP-connector registreren
connector = client.connectors.create(
    name="orion-db",
    type="mcp",
    endpoint="https://your-mcp-server.example.com"
)

# Agent-call met verplichte goedkeuring per tool-call
response = client.agents.complete(
    model="mistral-medium-3.5",
    messages=[{"role": "user", "content": "Analyseer de laatste deployments"}],
    connectors=[connector.id],
    approval_mode="required"
)
```

Built-in connectors voor GitHub, Gmail en web search komen pre-geconfigureerd. Alle connectors zijn centraal geregistreerd en beschikbaar in Le Chat, AI Studio en — binnenkort — Vibe. Programmatisch kun je connectors aanmaken, aanpassen, verwijderen, hun tools inspecteren en direct aanroepen.

De implicatie voor MCP-servers die jullie al bouwen: ze zijn zonder aanpassingen compatibel met Claude Code, de OpenAI Agents SDK én Mistral Studio. Provider-agnostische integration tests in jullie CI-pipeline worden daardoor zinvol — je detecteert zo of een model-switch of API-update gedragsveranderingen geeft in hoe tool-calls worden geformuleerd.

## Tot slot

De drie providers implementeren MCP elk met een andere nadruk. Anthropic focust op enterprise-governance (managed settings, per-MCP-server cost monitoring). OpenAI focust op execution-isolatie (de relay-architectuur). Mistral focust op expliciete human-in-the-loop control (approval-mode per tool-call). Dat geeft een aardig beeld van hoe elk bedrijf de risico's van agentic AI weegt.

Nu MCP universeel is, verschuift de differentiatie naar de kwaliteit van de implementaties: sandboxing van tool-responses, foutafhandeling bij trage servers, caching-semantiek over sessies heen. Interessant om te volgen welke provider daar het eerste een overtuigend antwoord op geeft.
