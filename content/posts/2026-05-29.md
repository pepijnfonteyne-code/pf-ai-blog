De modelreleasecyclus versnelt zichtbaar: twee weken na Opus 4.7 is er al Opus 4.8, terwijl GPT-5.5 bij OpenAI het standaard model overneemt. Parallel consolideert het open-weight ecosysteem rond een handvol modellen die closed frontier niet alleen benaderen maar op specifieke agentic benchmarks inhalen. De toolinglaag erboven — governance, execution sandboxing, memory management — volwassener snel mee.

Wat opvalt is de structuur van de concurrentie: drie ecosystemen bewegen tegelijk, maar langs verschillende assen. Anthropic zet in op context en betrouwbaarheid (1M tokens, minder fouten in gegenereerde code). OpenAI verfijnt de UX van reasoning-control. En de open-weight community bewijst steeds nadrukkelijker dat MIT-licentie, sparse MoE-architectuur en lage inferentiekosten samen een serieuze propositie zijn voor productie-agents.

## Claude Code — Opus 4.8: 1M context en Dynamic Workflows in research preview

**Opus 4.8** werd op 28 mei via API, Amazon Bedrock, Google Cloud Vertex AI en Microsoft Foundry beschikbaar. Model-ID: `claude-opus-4-8`. De belangrijkste cijfers:

- Context: 1M input tokens, 128k output tokens
- SWE-bench agentic coding: 69.2% (vs 64.3% voor Opus 4.7)
- 4x minder foutgevoelig in gegenereerde code (internal benchmark)
- Prijs: $5/$25 per miljoen tokens (Fast mode: $10/$50)

Het is een hybride reasoning model — net als o1 en Gemini 3.5 Flash — dat intern chain-of-thought stappen zet vóór het antwoord zichtbaar is. De scoresprong op agentic coding is groter dan de stap van Opus 4.6 naar 4.7, wat suggereert dat de architectuurkeuzes voor agentic use cases gerichter zijn geworden.

Voor Orion is de upgrade een drop-in replacement:

```python
client = Anthropic()

# Zelfde interface, 128k output en 1M context beschikbaar
response = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=128000,
    messages=[{"role": "user", "content": prompt}]
)
```

Tegelijk met de release ging **Dynamic Workflows** in research preview. Waar `/goal` een specifieke conditie als eindtoestand definieert, is Dynamic Workflows een niveau hoger: Claude maakt zelf subtaken aan op basis van de hoofd-instructie, delegeert die naar worker-agents en consolideert de resultaten. De **`claude agents`** TUI toont in real-time welke sessies actief, geblokkeerd of klaar zijn — vergelijkbaar met een process-monitor maar dan voor agent-instanties:

```bash
claude agents
# SESSION_ID  MODEL        STATUS   TASK
# abc123      opus-4-8     running  refactor auth module
# def456      sonnet-4-6   blocked  waiting for tool approval
# ghi789      sonnet-4-6   done     write unit tests
```

`Ctrl+T` pinned sessions persistent over terminalrestarts. Rate limits zijn ook verdubbeld — niet toevallig, want Anthropic's SpaceX-deal ($1.25B/maand compute) maakt agressievere usage-policies structureel mogelijk.

## OpenAI — GPT-5.5 als nieuw standaard model en Codex reasoning controls

Op 22 mei verving OpenAI GPT-5.3 Instant door **GPT-5.5** als standaard ChatGPT-model. Via API zijn `gpt-5.5` en `gpt-5.5-instant` beschikbaar. GPT-5.5 scoort hoger op multi-step reasoning en tool use, al publiceert OpenAI geen vergelijkende benchmarks — wat inmiddels een patroon is.

Interessanter voor builder-gebruik zijn de **Codex TUI reasoning controls**: `Alt+,` verlaagt het reasoning effort-niveau, `Alt+.` verhoogt het. Dit is UX-niveau, maar het patroon is architectureel relevant: reasoning effort als runtime-parameter die de gebruiker midtaak kan aanpassen, zonder de API-call te herbouwen. Momenteel zit dit alleen in de Codex CLI — niet in de API — maar het is een interface-patroon dat je verwacht ook in programmatic clients te gaan zien.

Andere Codex-verbeteringen: verbeterde MCP profile handling in remote sessies, sterkere tool schemas voor remote connections, en case-insensitive search door conversation history. De MCP-verbeteringen sluiten aan op wat Anthropic al deed in enterprise MCP-config: sessies die remote draaien hebben andere MCP-routing nodig dan lokale sessies, en de tooling begint dat onderscheid expliciet te maken.

GPT-5.5 versus Opus 4.8: op agentic coding-benchmarks publiceert OpenAI geen directe cijfers. De focus van GPT-5.5's verbeteringen (reasoning, tool use, multi-step) overlapt sterk met waar Opus 4.8 op scoort. Voor wie beide ecosystemen gebruikt is de interessante vraag welk model beter presteert op de specifieke agentic workload — dat vereist eigen benchmarking, want de marketingcijfers zijn onvergelijkbaar.

## Hermes / Open Source — DeepSeek V4 Pro en Qwen 3.6 Plus

De open-weight agentic benchmarks van mei 2026 laten twee modellen zien die de kloof met closed frontier serieus verkleinen.

**DeepSeek V4 Pro** (MIT-licentie) is een sparse MoE-model met 1.6T totale parameters maar slechts 49B actief per forward pass. De architectuur gebruikt MLA attention (Multi-head Latent Attention) voor efficiënte KV-cache bij lange contexten — relevant voor 1M-context sessies zonder lineaire geheugengroei. GDPval-AA Elo-ranking: 1554 (nr. 1 open-weight). Kosten: 10-13x goedkoper dan Opus 4.7 bij vergelijkbare throughput.

```bash
# Via Ollama (quantized versie)
ollama pull deepseek-v4-pro:q4_k_m

# Via DeepSeek API endpoint
curl https://api.deepseek.com/v1/chat/completions \
  -H "Authorization: Bearer $DEEPSEEK_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-v4-pro", "messages": [...]}'
```

**Qwen 3.6 Plus** (Apache 2.0) bereikt 78.8% op SWE-bench en 94% first-attempt tool call accuracy. Dat laatste getal is relevant voor MCP-integraties: tool calls die de eerste keer fout gaan in een agentic loop veroorzaken cascaderende fouten. 94% reduceert dat significant. Opgelet: Qwen 3.6 heeft altijd een `reasoning_content` veld in elke response, ook bij niet-reasoning-taken. Bij JSON-parsing van responses moet je dat veld bewust verwerken:

```python
response = client.chat.completions.create(
    model="qwen3.6-plus",
    messages=[...]
)

# reasoning_content zit in message.model_extra, niet in .content
content = response.choices[0].message.content
reasoning = response.choices[0].message.model_extra.get("reasoning_content", "")
```

Voor bulk agentic taken — code review, documentatie-generatie, testschrijven — is de combinatie van lage kosten en hoge tool-call accuracy een serieus alternatief of complement aan Opus 4.8.

## Open Source Tools — Microsoft agent-governance-toolkit en OWASP Agentic Top 10

**Microsoft agent-governance-toolkit** (3.2K GitHub stars) implementeert de OWASP Agentic Top 10 als concrete policy-enforcement laag. Het werkt op instantieniveau: elke agent-instantie krijgt een policy-profiel dat bepaalt welke tools toegankelijk zijn, welke acties pre-approval vereisen, en in welke execution sandbox de agent draait.

De kernconcepten:
- **Zero-trust identity per instantie**: agent A mag geen acties uitvoeren als agent B, zelfs bij identieke configuratie
- **Execution sandboxing**: gedefinieerde grenzen voor filesystem, netwerk en externe services per agent
- **OWASP Agentic Top 10 coverage**: prompt injection, excessive agency, insecure output handling — detection- en blocking-layers voor alle tien

```yaml
# Voorbeeld policy voor een Orion code-review agent
agent_policy:
  id: code-review-agent
  identity:
    trust_level: restricted
    allowed_tools: [read_file, create_comment, get_pr_diff]
    denied_tools: [write_file, execute_command, network_request]
  sandbox:
    filesystem: read-only
    network: none
  approval_required:
    - tool: create_comment
      condition: "confidence < 0.8"
```

**Honcho** (4.4K stars) biedt persistent memory management voor stateful agents: een memory store met context-aware retrieval. In tegenstelling tot simpele vector stores beheert Honcho de levenscyclus van memories — recent, verouderd, conflicterend — en biedt een API voor agents om geheugen expliciet te lezen, schrijven en te resetten. Vergelijkbaar met wat Anthropic's Dreaming doet op Managed Agents-niveau, maar dan als open-source bibliotheek die je in elke agentic stack kunt pluggen.

De combinatie van agent-governance-toolkit en Honcho dekt twee complementaire behoeften: wat een agent mag doen (governance) en wat hij onthoudt (memory). Beide zijn voorwaarden voor agents die weken stabiel blijven in productie.

## Tot slot

Simon Willison observeerde dat zowel Anthropic als OpenAI hun eerste winstgevende kwartaal in zicht hebben. Zijn analyse: product-market fit is gevonden, de schaal volgt. Dat verklaart ook de rate limit-verdubbeling bij Claude Code en de versnelde modelreleasecyclus — het zijn niet louter technische keuzes maar zakelijke.

De spanning die blijft is die tussen modelsnelheid en infrastructuurvolwassenheid. Elke twee weken een nieuwe frontier-release is één ding. Een productie-agentic-stack die maanden stabiel blijft met dezelfde API-surface, tool schemas en memory-structuur is iets anders. Governance-tooling zoals de agent-governance-toolkit is precies de laag die die stabiliteit maakt — niet het model, maar de contracten rondom het model.
