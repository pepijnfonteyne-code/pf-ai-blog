## Claude Code — Dynamic Workflows: orchestratie buiten het context-window

Dynamic Workflows is niet gewoon "meer agents tegelijk". De architectuurkeuze eronder is fundamenteel anders dan wat Claude Code eerder deed: in plaats van dat Claude alle loop-logica, branch-conditions en intermediaire resultaten in zijn context-window bijhoudt, **schrijft Claude een JavaScript-orchestratiescript** dat een aparte background runtime uitvoert. Claude's eigen context ontvangt enkel het eindantwoord.

```javascript
// Parallelle security review over een volledige codebase
const workflow = await claude.createWorkflow({
  concurrency: 16,           // max gelijktijdig actieve agents
  maxAgents: 200,            // ceiling voor deze specifieke run
  strategy: "adversarial"    // agents refuteren elkaars bevindingen iteratief
});

const files = await workflow.glob("src/**/*.ts");

const reviews = await workflow.mapParallel(files, async (file) => {
  return await workflow.agent(`Review ${file} for security vulnerabilities`);
});

// Synthesis-agent ontvangt alleen de reviews, niet alle intermediaire stappen
await workflow.agent(`Synthesize and prioritize findings:\n${reviews.join("\n")}`);
```

De `adversarial` strategy is het meest interessante onderdeel: agents werken vanuit onafhankelijke invalshoeken en itereren totdat hun antwoorden convergeren. Het token-budget van elke individuele agent blijft klein omdat tussenresultaten buiten Claude's context bestaan — opgeslagen in de runtime, niet in het model. De hard ceiling zit op 1.000 agents per run, 16 gelijktijdig actief.

Het praktische bewijs van haalbaarheid: Jarred Sumner porteerde 750.000 regels van Bun van Zig naar Rust in elf dagen via precies dit patroon. Dat is normaal een maandenlang traject.

Vereisten: Claude Code v2.1.154+, betaald plan (of AWS Bedrock / Google Cloud Vertex AI / Microsoft Foundry). Workflow-scripts genereer je door in Claude Code te typen: "maak een Dynamic Workflow voor [doel]" — Claude schrijft het JS-script, jij monitort via Agent View.

Voor grotere Orion-taken is dit direct inzetbaar: parallelle code-review pipelines waarbij meerdere agents vanuit verschillende abstractieniveaus naar dezelfde codebase kijken, grootschalige documentatiegeneratie waarbij een synthesis-agent de style-consistency bewaakt, of refactors waarbij elke module door een onafhankelijke agent aangepakt wordt.

## Gemini — Interactions API: outputs→steps migratie, deadline 8 juni

Dit is de meest tijdgevoelige update van het moment. Google heeft per 26 mei het nieuwe `steps`-schema als standaard ingesteld voor de Gemini Interactions API. Vanaf **8 juni** verdwijnt het legacy-schema permanent — alles wat nog `outputs` gebruikt, breekt dan zonder waarschuwing.

Het structurele verschil:

```python
# OUD — legacy schema, stopt te werken na 8 juni
response = client.interactions.create(model="gemini-2.5-pro", ...)
for output in response.outputs:        # outputs-array: deprecated
    print(output.content)

# NIEUW — vereist Python SDK >=2.0.0
response = client.interactions.create(model="gemini-2.5-pro", ...)
for step in response.steps:           # steps-array: user_input + model_output types
    if step.type == "model_output":
        print(step.content)
```

De `steps`-array introduceert twee step-types (`user_input` en `model_output`) en nieuwe SSE-event types: `interaction.created` en `step.delta` vervangen de bestaande streaming events. `response_format` vervangt `response_mime_type` als polymorf configuratie-object — let op overal waar MIME-types hardcoded staan in streaming consumers.

Tijdelijk opt-out via de header `Api-Revision: 2026-05-07` is mogelijk, maar enkel tot 8 juni. Gebruik het als tijdelijke buffer voor migratie, niet als permanente fix.

Tegelijk gelanceerd: `gemini-embedding-2-preview`, de eerste Gemini embedding die tekst, afbeelding, video, audio én PDF in één unified vector space mapt. Voor RAG-pipelines die nu apart text-embeddings en image-embeddings beheren opent dit cross-modal retrieval zonder twee aparte indexpipelines te hoeven onderhouden.

Migratie-pad: `pip install google-generativeai --upgrade` voor Python SDK >=2.0.0, `npm install @google/generative-ai@latest` voor JavaScript. Zoek in de codebase op `response.outputs`, `.outputs[`, en `response_mime_type` als startpunt voor de audit.

## Open Source Tools — claude-plugins-official: 101 plugins als pure markdown+JSON

Het officiële plugin-ecosysteem rond Claude Code staat deze week in de GitHub trending top 5 — 4.858 nieuwe stars in zeven dagen. De aanleiding: 101 plugins beschikbaar, 33 Anthropic-gebouwd en 68 partner-plugins van GitHub, Playwright, Supabase, Figma, Vercel, Linear, Sentry en Stripe.

Wat maakt dit anders dan een gerangschikte MCP-serverlijst? Een plugin bundelt drie architecturele lagen in één installeerbaar pakket:

1. **SKILL.md** — expertise die automatisch activeert op basis van context (geen expliciete aanroep nodig)
2. **Slash commands** — expliciete gebruikersacties die je zelf aanroept
3. **Connectors** — MCP-servers die lokaal geïnstalleerd worden bij plugin-installatie

De volledige plugin-architectuur is declaratief. Geen codeerwerk vereist:

```json
{
  "name": "supabase-workflow",
  "version": "1.0.0",
  "skills": ["SKILL.md"],
  "commands": ["commands/migrate.md", "commands/seed.md"],
  "connectors": [
    {
      "name": "supabase",
      "mcp_server": "@supabase/mcp-server-supabase",
      "config": { "project_ref": "${SUPABASE_PROJECT_REF}" }
    }
  ]
}
```

De `knowledge-work-plugins` repo van Anthropic (open source, 11 plugins) is de beste referentie voor plugin-structuur. SKILL.md beschrijft **wanneer** de skill automatisch moet activeren — contextueel, niet op command. Dat onderscheidt een skill van een slash command: de skill injecteert zich in de juiste context zonder dat de gebruiker eraan moet denken.

Eigen plugins bouwen: pak een bestaande MCP-server in als connector, schrijf een SKILL.md die de activatiecondities beschrijft, en je hebt een distribueerbaar pakket dat collega's installeren zonder zelf configuraties te kennen. Supabase- en Linear-plugins zijn direct inzetbaar voor database workflows en project management in Claude Code.

## AI Builders — Simon Willison: MCP token-overhead als productie-bottleneck

Simon Willison publiceert zelden iets zonder meetbare grond. Zijn observatie van afgelopen week: GitHub's officiële MCP-server verbruikt alleen al tienduizenden tokens context per sessie. Dat maakt MCP's grootste praktische beperking in productie niet de protocol-complexiteit of de setup — maar het token-budget.

De implicatie is concreet: drie of vier zware MCP-servers actief, en de tool-definitielaag vreet een significant deel van je context-window op vóór er ook maar één prompt verwerkt is. Het probleem schaalt lineair met het aantal actieve servers, en is stil — je krijgt geen foutmelding, je context krimpt gewoon.

Zijn tweede observatie is opmerkelijker: hij beschouwt Claude Skills als "possibly a bigger deal than MCP" voor context-efficiënte capability injection. Skills activeren op basis van context en injecteren alleen wat relevant is — geen volledig tool-manifest dat bij elke sessie opnieuw geladen wordt. Dat verschil wordt pas zichtbaar in productie-setups met meerdere gelijktijdige capabilities.

Praktisch: in Claude Code is het token-verbruik per sessie zichtbaar via `/usage`. Zware MCP-servers zijn kandidaten om te vervangen door Skills waar de capability declaratief te beschrijven is. GitHub MCP als specifiek voorbeeld: voor de meeste code-review use cases volstaat een GitHub-skill die bij relevante context automatisch activeert, zonder de volledige MCP-server actief te houden.

## Tot slot

De rode draad van vandaag is dezelfde die de afgelopen weken zichtbaar werd: de tooling-laag consolideert, maar de subtiele limieten worden pas nu duidelijk. Token-budget is de nieuwe contextlimiet. Plugin-architectuur is de nieuwe MCP-distributie. En een migratiedeadline van tien dagen laat weinig ruimte voor later.

De hardste takeaway blijft de Gemini-deadline: 8 juni is niet flexibel. Elk team dat Gemini Interactions API gebruikt — in RAG-pipelines, streaming consumers, of embedded agents — heeft nu minder dan tien dagen om de `outputs`-→-`steps`-migratie af te ronden. Daarna breekt het stilletjes.
