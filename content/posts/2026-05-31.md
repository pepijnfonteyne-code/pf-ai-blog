De week van 31 mei draait niet om nieuwe modellen of spectaculaire benchmarks. De grotere beweging ligt een laag dieper: het protocol dat AI-agents aan hun tools koppelt, consolideert rond een stateless architectuur die productie-deployment structureel vereenvoudigt. Tegelijkertijd bewijst het open-weight ecosysteem opnieuw dat sparse MoE niet alleen een efficiëntiehack is, maar een volwaardige architectuurkeuze voor productie-agentic workloads.

Vier ontwikkelingen bepalen het beeld vandaag. De MCP 2026-07-28 Release Candidate is gelocked — tien weken SDK-validatie voor de finale publicatie. Kimi K2.6 verschijnt als #4 in de Artificial Analysis Intelligence Index met open weights en een Agent Swarm die schaalt naar 300 gespecialiseerde subagents. QwenPaw v1.1.9 implementeert al de OAuth 2.1 auth-laag uit diezelfde MCP RC als open-source referentie. En Simon Willison demonstreerde op Code w/ Claude 2026 hoe README-driven development de spanning tussen vibe coding en agentic engineering praktisch oplost.

## MCP — 2026-07-28 Release Candidate: stateless core, Tasks en OAuth/OIDC

Op 21 mei werd de RC van de MCP 2026-07-28 specificatie gelocked — de grootste revisie van het protocol, nu in een 10-weekse SDK-validatieperiode vóór finale publicatie. Drie structurele veranderingen zijn het noemen waard.

**Stateless protocolkern.** Elke HTTP-request wordt zelfstandig: geen server-side sessiestatus meer. Dat klinkt als een detail, maar het is een infrastructurele vereenvoudiging met directe gevolgen. Horizontaal schalen van MCP-servers wordt trivial: geen sticky sessions, geen load balancer-configuraties voor sessierouting, geen herstellogica bij server-crashes. Bestaande MCP-serverimplementaties die state bijhouden in het serverproces hebben een refactor nodig. De transitiewindow loopt tot 28 juli.

**Tasks-extensie.** Langlopende agentic workflows worden gemodelleerd als formele taakobjecten met statusupdates en callbacks. Tot nu toe was er geen standaard manier om een agent-taak te starten, de voortgang op te vragen en het resultaat op te halen — elke toolmaker rolde zijn eigen polling-mechanisme. Tasks formaliseert dit patroon direct in het protocol:

```json
{
  "type": "task",
  "id": "task_abc123",
  "status": "running",
  "progress": {
    "percent": 42,
    "message": "Analyzing file 420/1000"
  },
  "created_at": "2026-05-21T10:00:00Z"
}
```

Een MCP-server die langlopende code-analyse aanbiedt, kan nu een task starten en statusupdates pushen via het standaard callback-mechanisme — zonder dat de client een custom polling-loop hoeft te implementeren. Dat maakt Tasks tot een directe bouwsteen voor Orion-workflows die nu afhankelijk zijn van ad-hoc status-checks.

**OAuth/OIDC-hardening.** De nieuwe auth-laag sluit nauwer aan bij OAuth 2.0 en OIDC, inclusief een formele deprecation policy voor toekomstige breaking changes. Dat laatste detail is onderschat: de MCP-spec is tot nu toe snel geëvolueerd zonder stabiele guarantees. Een formele deprecation policy maakt productie-investment minder risicovol.

Tegelijkertijd publiceerde de NSA beveiligingsrichtlijnen specifiek voor MCP-gebaseerde AI-automatisering. Als security checklist bruikbaar vóór elke productie-deployment van MCP-servers — de combinatie van NSA-richtlijnen en OAuth/OIDC-hardening geeft een duidelijk signaal: de fase van "MCP als hobbyprotocol" eindigt.

De practische actie: audit je bestaande MCP-server-implementaties nu op server-side state. Als ze sessie-informatie bijhouden in memory, plan de refactor vóór 28 juli.

## Hermes / Open Source Models — Kimi K2.6: 1T MoE en Agent Swarm

Moonshot AI's Kimi K2.6 staat op #4 in de Artificial Analysis Intelligence Index (score 54), direct achter de top closed models van Anthropic, Google en OpenAI. Dat is al opmerkelijk — maar de architectuur is het vermelden waard.

K2.6 is een 1-triljoen parameter MoE-model met slechts 32B actieve parameters per token, vergelijkbaar in inferentiekost met een 32B dense model. De Agent Swarm-feature schaalt naar 300 domein-gespecialiseerde subagents voor maximaal 4.000 gecoördineerde stappen in één autonome run. Als referentiepunt: Claude's Dynamic Workflows schalen naar 1.000 parallelle subagents, maar K2.6 biedt dat in open-weights formaat met volle lokale-deployment-optie.

```python
from kimi import AgentSwarm

swarm = AgentSwarm(
    model="kimi-k2.6",
    specialists=["security-analyst", "performance-engineer", "test-architect"],
    max_steps=4000
)

result = await swarm.run(
    task="Refactor authentication module: security review + perf benchmark + test coverage",
    codebase_path="./src/auth"
)
```

Het model is beschikbaar via HuggingFace als open weights en via de Kimi API, wat lokale deployment via vLLM of Ollama mogelijk maakt. Voor use cases waar je geen gesloten model data wilt sturen — interne codebases, klantdata, compliance-gevoelige workloads — is dit het eerste open-weight model dat serieus als alternatief voor Claude of GPT-5.5 functioneert op agentic coding taken.

De kanttekening is eerlijk: 1T parameters hosten is niet triviaal. Zelfs met 32B actief per token heb je significant VRAM nodig voor lokale inference op volledige snelheid. De Kimi API is de realistische weg voor de meeste productie-deployments. Maar de open-weights beschikbaarheid zelf is het principe — fine-tuning, audit en lokale runs zijn wel degelijk mogelijk.

## Open Source Tools — QwenPaw v1.1.9: Coding Mode en OAuth 2.1 MCP

QwenPaw, de open-source persoonlijke AI-assistent op Qwen-basis, bracht in mei drie snelle releases uit. De meest substantiële verbetering in v1.1.9 (14 mei) is Coding Mode: een volledig IDE-layout met file tree, tabbed editor met inline diff review en Git-panel — als laag bovenop het conversatie-interface, niet als vervanging ervan.

Wat technisch relevant is: v1.1.7 implementeerde al OAuth 2.1 MCP-support, wat geauthenticeerde MCP-serververbindingen mogelijk maakt in een open-source client. Dat is niet toevallig synchroon met de MCP RC — QwenPaw loopt actief voor op de finale specificatie als open-source referentie-implementatie. Waar de meeste MCP-clients nog op de oude auth-laag draaien, implementeert QwenPaw de nieuwe spec al.

De inline diff review in Coding Mode werkt conceptueel vergelijkbaar met Claude Code's `/review`-skill: wijzigingen verschijnen inline in de editor met accept/reject controls per hunk. Het verschil is dat QwenPaw dat als standalone desktop app doet, zonder te vereisen dat je in een terminal-omgeving werkt. Voor teams die AI-assisted code review willen zonder full Claude Code commitment is dit een bruikbaar open-source alternatief, beschikbaar onder Apache 2.0.

De combinatie van OAuth 2.1 MCP en Coding Mode maakt QwenPaw tot een interessante referentie voor hoe een open-source MCP-client eruitziet als de RC op 28 juli finaliseert — handig als benchmark naast je eigen MCP-client-implementatie.

## AI Builders — Simon Willison: README-driven development als brug

Op Code w/ Claude 2026 (6 mei) formuleerde Simon Willison de spanning die iedereen voelt die serieus bouwt met AI-coding tools: vibe coding en agentic engineering convergeren qua tooling — beiden gebruiken Claude Code — maar divergeren qua mindset. Vibe coding is ongestructureerd en intuïtief; agentic engineering is deterministisch en spec-gedreven.

Zijn practische oplossing is README-driven development: schrijf eerst de volledige README als functionele spec, geef die als prompt aan Claude Code, en laat Claude de implementatie + tests bouwen met red/green TDD. De demo op het event: 30 minuten, een repo met 100+ commits en uitgebreide testcoverage.

De architectuurlogica: de README fungeert als formele spec die Claude direct vertaalt naar code. De menselijke specificatie en de LLM-implementatie zijn van tevoren aligned, zonder iteratieve correctieronden achteraf. De `/goal`-command is direct inzetbaar als completion condition:

```
/goal README beschrijft alle features die volledig werkend zijn, inclusief tests die slagen
```

De methode is direct overzetbaar naar Orion-componenten: definieer een nieuw component als README-spec — wat je toch al zou schrijven — gebruik die als Claude Code prompt met `/goal` als completion condition. Het elimineert de "wat moet ik precies builden?"-fase van elk nieuw feature-traject, zonder extra overhead toe te voegen.

Willisons kernobservatie is bescheidener dan de demo doet vermoeden: de snelheidswinst van AI-coding betaalt zich alleen terug als je die winst ook investeert in kwaliteit. Een README-spec die je toch al zou schrijven kost niets extra — maar geeft Claude de context om de eerste keer goede code te schrijven in plaats van na vier correctieronden.

## Tot slot

De stateless core in de MCP RC verandert hoe je MCP-servers infrastructureel opzet — maar de echte impact is pas volledig voelbaar als de Tasks-extensie ook live is: dan heb je een standaard manier om langlopende agent-workflows te orchestreren zonder custom polling-mechanismen. De vraag is of de 10-weekse SDK-validatieperiode genoeg is om de volledige toolinglaag — Claude Code, QwenPaw, Codex, vLLM-hosted Kimi — allemaal compatibel te krijgen vóór 28 juli. Tien weken is ambitieus.
