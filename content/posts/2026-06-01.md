## OpenAI — GPT-5.6 in backend canary, GPT-4.5 sunset bevestigd

GPT-5.6 is nog geen aankondiging, maar het bestaat al in Codex backend logs. Developers die API-calls naar Codex analyseerden, vonden model-referenties naar `gpt-5.6` in de response metadata — consistent met interne canary testing vóór bredere uitrol. Geen model card, geen benchmark, geen publieke endpoint. Polymarket zet de kans op een publieke release vóór 30 juni op 80-89%.

Relevanter voor de korte termijn: GPT-4.5 wordt op **27 juni** verwijderd uit ChatGPT. De 30-daagse sunset-periode is gestart. API-gebruikers die nog op `gpt-4.5` zitten moeten migreren naar `gpt-5.x` voor die datum, anders breken calls. Drie weken is niet veel buffer als er integration tests omheen zijn gebouwd.

OpenAI lanceerde ook Rosalind Biodefense op 29 mei — een domeinspecifiek model voor life sciences, aangeboden exclusief aan geselecteerde US-overheidspartners. Het illustreert de trend die we vaker gaan zien: parallelle specialisatie naast de general-purpose frontier. Hetzelfde patroon als Opus 4.8 naast Claude Sonnet, maar dan verticaal per sector in plaats van horizontaal per use case.

## Gemini — Antigravity Managed Agents in public preview

Naast de `outputs → steps` schema-migratie (deadline 8 juni) die we eerder behandelden, is er een grotere aankondiging van Google I/O 2026: de Managed Agents API is in public preview, aangedreven door het model `antigravity-preview-05-2026` op basis van Gemini 3.5 Flash (GA seit 19 mei).

Het model-id verraadt de architecturale keuze: dit is niet een dunne wrapper om een chat-API, maar een eigen agent harness. Één API call start een volledige agent die redeneert, tools gebruikt en code uitvoert in een geïsoleerde Linux container. File state is persistent across follow-up calls — je kunt een multi-turn agent-sessie opbouwen zonder zelf session management te schrijven.

```python
import google.generativeai as genai

client = genai.Client()
response = client.agents.run(
    agent_id="antigravity-preview-05-2026",
    prompt="Analyseer de dependencies in dit project en maak een upgrade-plan",
    files=[uploaded_file]
)
```

De architecturale parallel met Claude Code Dynamic Workflows is niet toevallig: beide benaderingen abstraheren het orchestratie-niveau weg van de developer. Het verschil zit in het doel — Dynamic Workflows richt zich op schaal (tot 1000 parallelle subagents met adversarial verification), Antigravity op geïsoleerde code-execution met file-persistentie per sessie. Als je een agent wilt die herhaaldelijk op dezelfde file tree werkt zonder session-state te managen, is Antigravity de directere keuze.

Gemini 3.5 Pro staat nog in de pipeline voor juni. Antigravity zal waarschijnlijk upgraden naar dat model zodra het GA gaat — houd de model-id in de gaten als je nu al op preview bouwt.

## AI Builders — Willison: agentic coding als echte PMF

Simon Willison publiceert op 27 mei een analyse die de vraag stelt die iedereen eigenlijk al stelt: heeft de AI-sector nu echt product-market fit? Zijn antwoord is ja, maar niet waar je het verwacht.

De PMF zit niet in consumer chat — die heeft hoge churn en lage switching costs. De PMF zit in agentic developer tooling, omdat de ROI er direct meetbaar is in sprint-velocity en code-throughput. Bedrijven betalen omdat ze de productiviteitswinst zien op de volgende sprint review. Dat is een andere dynamiek dan "we hebben 500 miljoen MAU" — dit zijn betalende enterprise-klanten die de tool niet weggooien omdat de alternatieven moeilijk te benchmarken zijn.

Willison onderbouwt het met Anthropic's $47 miljard run-rate revenue (per 29 mei), mede gedreven door de SpaceX Cloud Services Agreement van $1.25 miljard per maand tot 2029. Dat is een specifiek, lang contract van een engineering-organisatie — het type klant dat pas tekent als het aantoonbaar werkt.

Zijn [liveblog van Code w/ Claude 2026](https://simonwillison.net/2026/May/6/code-w-claude-2026/) (6 mei) is de meest gestructureerde primaire bron voor alle Anthropic-aankondigingen van de afgelopen weken: Dynamic Workflows, Opus 4.8, Managed Agents webhooks, en de dubbele rate limits voor Claude Code zijn er chronologisch gedocumenteerd. Bruikbaarder dan de verspreide press releases.

De implicatie voor de P&F-context: de PMF-shift betekent dat de vergelijkingsbasis verandert. "Welk model gebruik je?" wordt minder relevant dan "welk orchestratie-paradigma gebruik je?" — en het antwoord op die vraag bepaalt steeds meer welk model je überhaupt kunt inzetten.

## Open Source Tools — dograh brengt voice naar MCP, AgentScope voor observability

Twee projecten met sterk momentum op de GitHub Python trending list deze week:

**dograh** (+1329 stars deze week) is een open-source voice AI platform met native MCP connector. Het bouwt een brug tussen voice-interfaces en het MCP-tool ecosysteem — je kunt bestaande MCP-servers aanspreken via spraakcommando's zonder custom integratiecode te schrijven. Voor teams die al een MCP-stack hebben gebouwd, is dit de kortste route naar een voice UI. De architecturale keuze om MCP als protocol-laag te gebruiken in plaats van een eigen tool-abstraktie is opvallend — het signaleert dat MCP als standaard breed genoeg geaccepteerd is om als fundament te bouwen.

**AgentScope** (25.9K stars totaal, Microsoft Research) positioneert zich als "agents you can see, understand and trust." De kernpropositie is observability-first: elke agent-stap is traceerbaar en debuggable via een ingebouwde visualisatielaag, zonder een separate tracing infra zoals Langfuse of Honeycomb te hoeven opzetten.

```yaml
# AgentScope pipeline config
agent_configs:
  - agent_id: "code-reviewer"
    agent_type: "ReActAgent"
    model_config_name: "claude-opus-4-8"
    trace: true
    tools:
      - type: "code_executor"
      - type: "file_reader"
```

De combinatie is interessant als stack: dograh voor voice-input → MCP → agent pipeline met AgentScope-observability. Volledig open-source, voor elke stap inspecteerbaar.

Anthropic's knowledge-work-plugins repository (+4944 stars deze week, 18.4K totaal) verdient ook een blik. Het signaleert een apart spoor naast de generieke MCP-laag: domain-specific tool extensions voor Claude Cowork. Als referentie-architectuur voor Orion-specifieke Claude plugins de moeite waard om door te lopen.

## Tot slot

Het patroon dat zich aftekent is dat de orchestratielaag het nieuwe battleground is. Antigravity, Dynamic Workflows, AgentScope — ze concurreren niet op model-kwaliteit maar op hoe goed ze de complexiteit eronder abstraheren. Willison's PMF-argument suggereert dat dit de juiste laag is om op te winnen. Maar als alle platforms dezelfde orchestratieprimitieven aanbieden, waar zit dan de differentiatie over twee jaar?
