De afgelopen dagen verschuift de focus in het AI-ecosysteem van model-releases naar productie-architectuur. Drie ontwikkelingen illustreren dat: Codex die Windows-applicaties leert besturen, Genkit dat middleware-patronen introduceert voor robuuste AI-pipelines, en Gemini Spark dat MCP bevestigt als productiestandaard voor persistent agentic werk.

De thread die ze verbindt: AI tools rijpen van demo naar deployment. Computer Use, composable hooks en 24/7 cloud-resident agents zijn geen research-previews meer — ze zijn beschikbaar in enterprise-omgevingen en open-source frameworks die je vandaag kunt integreren.

## OpenAI — Codex krijgt Computer Use voor Windows-applicaties

OpenAI voegde Computer Use toe aan Codex, beschikbaar voor Enterprise en Edu workspaces. Waar Codex tot nu toe code schreef en uitvoerde via shell en API, kan het nu ook Windows-applicaties besturen: scherm observeren, muisbewegingen simuleren, typen in GUI-elementen van native apps.

De technische implementatie is vergelijkbaar met Anthropic's Computer Use API: screen capture gecombineerd met vision model inference identificeert UI-elementen, waarna gesimuleerde muis- en toetsenbordbewegingen de interactie uitvoeren. Het cruciale verschil met een standalone Computer Use implementatie is de integratie in de Codex coding agent flow — multi-step workflows die IDE, browser én native Windows tools combineren in één agentic run zijn nu mogelijk zonder handmatig schakelen tussen omgevingen.

Praktisch betekent dit dat je een Codex-sessie kunt starten die een ERP-systeem opent, data invoert, een rapport exporteert en dat rapport vervolgens verwerkt in code — allemaal zonder dat de applicatie een API aanbiedt. Voor legacy enterprise systemen (SAP, oudere interne tooling, Windows-only software) is dit de eerste geloofwaardige automatiseringsaanpak die geen screen-scraping bibliotheken of deprecated COM-interfaces vereist.

Relevante context: GPT-4.5 wordt deprecated op 27 juni 2026. OpenAI consolideert duidelijk richting agentic enterprise tools, waarbij Computer Use als layer bovenop bestaande agents wordt gepositioneerd in plaats van als apart product. De vergelijking met Claude's Computer Use voor dezelfde legacy-workflows is interessant: Anthropic's implementatie werkt platform-agnostisch, OpenAI's zit dieper verweven in de Codex workflow. Welke aanpak schaalbaar is voor Orion-doelstellingen verdient een directe benchmark op concrete enterprise use cases.

## Open Source Tools — Google Genkit krijgt composable Middleware

Google's open-source Genkit framework (Node.js en Go) introduceerde een middleware-systeem met composable hooks op drie niveaus: generate-level, model-level en tool-level. Dit is geen incrementele update — het lost een fundamenteel probleem op in AI-pipeline engineering: hoe zorg je dat retries, fallbacks en veiligheidscontroles consistent werken zonder ze in elke agent opnieuw te implementeren?

De architectuur werkt als volgt. Hooks zijn composable via een `pipe()` functie:

```typescript
const pipeline = pipe(
  retryWithBackoff({ maxAttempts: 3, baseDelay: 1000 }),
  modelFallback({ primary: 'gemini-flash', fallback: 'gemini-pro' }),
  toolApprovalGate({ requireApproval: ['write', 'delete', 'externalApi'] }),
  scopedFilesystem({ allowedPaths: ['/workspace'] })
);
```

**generate-level hooks** intercepten de volledige generatie-call — ideaal voor retry-logica en circuit breakers die je niet per-model wil herschrijven. **model-level hooks** wrappen individuele model inference — geschikt voor transparante fallback wanneer een provider rate-limited of tijdelijk down is. **tool-level hooks** intercepten tool-calls voor en na uitvoering — de meest waardevolle categorie voor productie-agents.

Twee specifieke patronen zijn direct toepasbaar:

*Tool approval gate als veiligheidsmechanisme*: In een productie-agent die bestanden manipuleert of externe services aanroept, wil je dat destructieve operaties niet autonoom verlopen. Een tool-level hook die `write`, `delete` en externe API-calls onderschept en naar een human-in-the-loop queue stuurt is nu vier regels code in plaats van custom middleware per agent. Dit is het patroon dat ontbreekt in de meeste agent-frameworks — niet de inference, maar de governance eromheen.

*SKILL.md injection als contextafhankelijke skill-loading*: Genkit ondersteunt SKILL.md-bestanden als middleware-geïnjecteerde context — exact hetzelfde formaat als Claude Code skills. Dit maakt dynamisch skill-laden mogelijk op basis van de actieve taakcontext, een patroon dat rechtstreeks overdraagbaar is naar eigen agent-architectuur zonder framework-lock-in.

De MCP-connector van Genkit stelt het framework in staat als orchestratie-laag te fungeren voor MCP-servers: Genkit wordt dan de middleware-bus tussen agents en tools, ongeacht welk onderliggend model de inference uitvoert. Dat maakt Genkit interessant als framework voor agent-pipelines die meerdere providers combineren.

## Gemini — Spark en de architectuurbevestiging van MCP als productiestandaard

Gemini Spark, aangekondigd op Google I/O 2026, is een 24/7 cloud-resident persoonlijke AI-agent die proactief handelt op basis van gebruikerscontext — calendar, email, chat — zonder directe prompts. Beschikbaar voor Google AI Ultra abonnees ($100/maand) in de VS, met initiële integraties in Gmail en Google Chat, en uitbreiding naar 30+ externe tools via MCP.

Het meest significante aspect van Spark is niet de functionaliteit. Een permanente, proactieve agent is concept-gewijs niet nieuw. Het significante is de architectuurkeuze: Spark is geïmplementeerd als MCP-client die verbinding maakt met MCP-servers van derde partijen. Dit is Google dat MCP als productiestandaard bevestigt op infrastructure-schaal — niet in een SDK of developer preview, maar in een consumentenproduct op hun productie-infrastructuur.

De 30+ MCP-servers die Google onboardt voor Spark zijn een waardevolle community-referentielijst: dit zijn de integraties die Google veilig genoeg acht voor een persistent, autonoom handelende agent met toegang tot gebruikersdata. Als MCP-serverontwikkelaar of Orion-architect is dit een directe validatieset voor welke server-implementaties production-grade worden beschouwd.

Technisch is Spark een stateful persistent agent: de taakplanning en context leven buiten het model's inference window, vergelijkbaar met hoe Dynamic Workflows in Claude Code batchoperaties orchestreren zonder context-window overhead. Het verschil is schaal en levensduur — Spark draait continu op achtergrondprocessen, Dynamic Workflows zijn task-scoped. Spark's architectuur geeft concrete inzichten over hoe je state beheert in een langlopende agent zonder het model de hele conversatiehistory te laten dragen.

De sunset van Gemini CLI op 18 juni 2026 is urgent voor iedereen met Gemini CLI-based workflows: de Managed Agents API is de officiële vervanging en de deadline is drie weken weg.

## Tot slot

Genkit's middleware-patterns, Codex's Computer Use en Spark's MCP-client architectuur hebben één gemeenschappelijke eigenschap: ze maken expliciet wat eerder impliciet was in agent-engineering. Veiligheidscontroles zitten nu in de pipeline, niet verstopt in elk prompt. GUI-automatisering zit in de agent flow, niet in aparte scripting-laag. MCP-integratie zit in de infrastructuur, niet in één-off connectors.

Als Google een productie-agent bouwt met 30+ MCP-servers als vanzelfsprekende infrastructuur, op welk punt wordt MCP-server kwaliteit en certificering een competitive differentiator voor platforms als Orion?
