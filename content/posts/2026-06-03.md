Drie bewegingen domineren deze week: Anthropic maakt Opus 4.8 de nieuwe standaard en lanceert Dynamic Workflows voor grootschalige agentic runs, het MCP-team publiceert een Release Candidate met fundamentele breaking changes op de transportlaag, en NousResearch levert met Hermes Agent v0.15 een open-source antwoord op skill-accumulation. De rode draad: orchestratie op grotere schaal.

De timing is scherp. De MCP RC-deadline (28 juli) en de Anthropic deprecation-deadline (15 juni) vallen in hetzelfde zomervenster. Twee audits die nu op de agenda moeten, niet volgende maand.

## Claude Code — Opus 4.8, Dynamic Workflows en een deprecation-deadline

De grootste praktische verandering van de week is niet een model maar een patroon: **Dynamic Workflows** in Claude Code. In plaats van een statische agent-graph schrijft Claude zelf een orchestratiescript dat tientallen tot honderden subagents parallel aanstuurt. De shift is van lineaire agentic execution naar een Claude-gegenereerde DAG die het probleem decomposed op basis van wat het ziet, niet op basis van wat een developer vooraf bedacht.

Concreet: bij een grootschalige refactor of multi-repo migration in Orion start je de run, Claude analyseert de scope, schrijft een orchestratieplan als script, en voert dat uit met parallelle subagents. De overhead van het opzetten van die structuur verdwijnt.

**Opus 4.8** is nu de standaard voor Max, Team Premium, Enterprise en API-accounts. De nieuwe `/effort xhigh`-flag is bedoeld voor de zwaarste taken — documenteer welke runs er baat bij hebben en welke overkill zijn. Fast Mode staat op $10/$50 per MTok, 3× goedkoper dan de vorige generatie.

De **security-guidance plugin** integreert als proactieve SAST-laag in de edit-loop: Claude reviewt wijzigingen real-time op kwetsbaarheden terwijl je werkt, niet pas bij een aparte scan. Activeer dit standaard bij elke sessie die productie-code raakt.

En dan de urgente deadline: **15 juni** worden `claude-sonnet-4` en `claude-opus-4` geretireerd van de Claude API. Alle hardcoded model-strings in MCP-servers, agent-configs en API-calls moeten migreren naar `claude-sonnet-4-6` respectievelijk `claude-opus-4-7`. Scan nu:

```bash
# Snel scannen op deprecated model-strings
grep -r "claude-sonnet-4[^-]" . --include="*.py" --include="*.json" --include="*.yaml"
grep -r "claude-opus-4[^-]" . --include="*.py" --include="*.json" --include="*.yaml"
```

Parallel gelanceerd: **Claude Platform op AWS** met IAM-authenticatie en AWS-billing. Messages API, Files API, Message Batches API en Managed Agents draaien nu vanuit AWS-infrastructuur zonder aparte API-key management. Relevant als Orion-workloads toch al op AWS draaien.

## MCP — Release Candidate: stateless core, Tasks-extensie, breaking changes

Het MCP-team publiceerde de Release Candidate voor de **2026-07-28 specificatie** — de meest ingrijpende revisie sinds launch. Drie veranderingen om te kennen:

**1. Stateless HTTP-core.** Geen persistente WebSocket-sessies meer. Elke `tools/call` is een standalone HTTP-request. Dat maakt MCP-servers horizontaal schaalbaar op standaard infrastructuur (load balancers, serverless functions), maar breekt elke server die state in de sessie bijhoudt.

**2. Tasks-extensie.** Bij lang-lopende tools geeft de server een `task_handle` terug. De client pollt asynchroon via `tasks/get` of annuleert via `tasks/cancel`. Dit is de juiste abstractie voor agentic runs die minuten of uren duren — tot nu toe had MCP geen antwoord op dat patroon.

```json
{
  "task_id": "task_abc123",
  "status": "running",
  "progress": 0.45,
  "estimated_completion": "2026-06-03T10:42:00Z"
}
```

**3. MCP Apps.** Servers kunnen interactieve HTML-UI's shippen die de host rendert in een sandboxed iframe. Claude Desktop wordt zo een runtime voor server-gedefinieerde interfaces — interessant voor tooling die meer dan text-output nodig heeft.

Authorization migreert naar OAuth 2.0 + OpenID Connect. Tier 1 SDKs moeten binnen het 10-weken validatievenster support shippen. Actie: audit welke van jullie MCP-servers stateful zijn (WebSocket/SSE) en plan migratie vóór 28 juli. De Tasks-extensie is bijzonder relevant voor Orion's lange agent-runs.

## Hermes/Open Source Models — Hermes Agent v0.15 en skill-writeback

NousResearch releasede Hermes Agent v0.15 (747-PR release, 28 mei) met een mechanisme dat in de agentic space relatief uniek is: **skill-writeback**. Nadat een complexe taak voltooid is, schrijft de agent automatisch een herbruikbare skill-definitie terug naar zijn skill-library. Vergelijkbare taken worden daarna sneller uitgevoerd zonder herbedachte orchestratie.

Het is conceptueel verwant aan Claude Code's `.claude/skills` auto-loading uit Week 22, maar model-native en cross-session persistent: de skill wordt opgeslagen als structureel artefact, niet als conversatie-context. Hermes 3 draait op Llama 3.1 base (3B, 8B, 70B, 405B varianten) — lokaal inzetbaar voor privacy-gevoelige workflows.

160.000+ GitHub stars in 12 weken — sneller dan OpenClaw — zegt iets over de community-tractie rond open-source agentic tooling. Als een agent zijn eigen capabilities opbouwt na gebruik, verandert de ROI-curve van een deployment structureel: de tiende run kost minder dan de eerste, en dat schaalt.

## AI Builders — Simon Willison over product-market fit en budget-exhaustion

Simon Willison's analyse van 27 mei is de meest directe observatie van AI-adoptie die ik deze week las. Zijn these: Anthropic en OpenAI hebben echte product-market fit bereikt. Het bewijs: Uber soupeerde in 2026 zijn volledig jaars-AI-budget op in enkele maanden, grotendeels door Claude Code dat pas echt goed werd in november 2025.

Dat is een structurele observatie. AI gaat van "experiment met budget-buffer" naar "kritieke infrastructuur zonder buffer". Budgetmodellen die uitgaan van een vast AI-kwartaalbudget breken als de productiviteitssprong groot genoeg is dat teams meer willen gebruiken dan voorzien.

Willison lanceerde ook **Datasette Agent** (21 mei) — een extensible AI-assistent bovenop Datasette, het open-source databasing framework. Concrete implementatie: natuurlijke taal queries op SQLite-databases via een MCP-integratie. Een goede referentie voor hoe je een bestaand tool-ecosysteem AI-enabled maakt zonder de tool zelf te herschrijven.

## Tot slot

De twee deadlines — 15 juni en 28 juli — zijn concrete actiepunten, geen toekomstige planning. Het interessantere patroon eronder: Dynamic Workflows, Hermes skill-writeback en MCP Tasks convergeren naar hetzelfde idee. Agents die hun eigen structuur bepalen, onthouden wat ze leerden, en lang-lopende werk asynchroon managen. De vraag is niet of dat de standaard wordt — maar wanneer het voor jullie workflows de default is.
