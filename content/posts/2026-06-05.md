Claude Code week 20-21 bracht twee features die samen de agentic workflow aanmerkelijk veranderen: `claude agents` als multi-session view en `/goal` als conditie-gestuurde loop. Ondertussen verschenen op Microsoft Build 2026 twee frontier modellen, rolde Hermes 0.14 uit als Foundation Release, en nadert de Gemini Interactions API breaking change van 8 juni.

Dit is geen theorie: elk van deze items raakt direct aan hoe je vandaag agents bouwt en deployt.

## Claude Code — Agent View en /goal: één terminal, meerdere sessies

`claude agents` is de nieuwe CLI-view die alle actieve Claude Code-sessies toont in één terminal: status, laatste respons, welke taken geblokkeerd zijn. Dat klinkt simpel, maar de implicatie is groot — je kunt meerdere agents parallel runnen, naar de achtergrond sturen, en pas terugkomen als er input nodig is.

```bash
claude agents          # overzicht alle actieve sessies
claude agents attach   # spring naar een specifieke sessie
```

`/goal` voegt een programmatische completion-conditie toe: Claude evalueert na elke turn of de conditie geldt, anders gaat hij door. Praktisch voorbeeld:

```
/goal "alle TypeScript-errors zijn opgelost en npm run build slaagt"
```

Claude loopt dan zijn eigen feedback-loop: schrijf fix → run build → evalueer → herhaal. Dat is een ander paradigma dan "geef Claude een opdracht en kijk wat er uit komt". Je definieert het succescriterium, Claude bouwt het pad er naartoe.

Auto Mode Pro (week 21) breidt dit uit naar Pro-accounts: permission prompts worden vervangen door background safety checks. Naast Opus 4.8 is nu ook Sonnet 4.6 selecteerbaar als model voor Auto Mode — relevant voor taken waarbij je latency en kosten wilt minimaliseren maar toch autonomie wilt.

De combinatie `claude agents` + `/goal` + Auto Mode maakt het voor het eerst haalbaar om een fleet van gespecialiseerde agents parallel te runnen vanuit één terminal, met Sonnet voor snelle taken en Opus voor de zware, zonder constant terug te hoeven komen voor permissions. `/usage` per skill en subagent geeft je daarna het inzicht om te beslissen welke taken downgrade-kandidaten zijn.

## Gemini — 3.5 Flash GA, Managed Agents en een urgente migratiedeadline

Op Google I/O 2026 werd Gemini 3.5 Flash GA gelanceerd: $1,50 input / $9 output per MTok, 4× hogere output-token throughput dan de Flash-lijn tot nu toe, en op coding en agentic benchmarks beter dan Gemini 3.1 Pro. Relevante datapoint: Gemini 3.5 Pro staat gepland voor later in juni — Flash is de instappoort naar een sterkere Pro-versie die eraan zit te komen.

Managed Agents gaan in public preview: stateful, autonome agents in Google-hosted Linux-sandboxen met persistente state, webaccess, code-executie en file management. Structureel vergelijkbaar met Claude's Dynamic Workflows (week 22), maar volledig Google-hosted en via de Vertex AI API aanstuurbaar. Antigravity Agent is de eerste ingebouwde managed agent voor generieke tasks.

**Urgente actie voor Gemini API-gebruikers**: de Interactions API heeft een breaking change op **8 juni 2026** — `outputs` wordt `steps`, en het legacy schema is volledig verwijderd. Als je Gemini API-calls hebt in productie, moet dit vóór aanstaande maandag gemigreerd zijn:

```python
# Oud (breekt op 8 juni)
response.outputs[0].text

# Nieuw
response.steps[0].text
```

Niet migreren vóór 8 juni betekent downtime. Geen optionele update.

## Hermes/Open Source Models — Hermes Agent v0.14.0: Foundation Release

NousResearch releasete Hermes Agent v0.14.0, gelabeld als Foundation Release. Drie features zijn direct relevant voor productiegebruik:

**180× snellere browser CDP-calls** via persistente WebSocket-verbindingen. Eerder werd per CDP-call een nieuwe verbinding opgezet; nu wordt één persistente WebSocket bijgehouden per browser-instantie. Voor browser-automation agents die veel DOM-interacties doen, is dit een meetbare verbetering in wall-clock tijd.

**Installatie via pip** maakt onboarding triviaal:

```bash
pip install hermes-agent && hermes
```

Cold start is ~19 seconden sneller door deferred imports. Voor lokale development is dat een merkbaar verschil bij frequent herstarten van de agent-omgeving.

**Cross-session Claude prompt caching** (1 uur TTL): Hermes slaat agent-context op en hergebruikt die in de volgende sessie via het native prompt caching protocol. Als jouw agent een vaste system prompt en toolset heeft — wat bij Orion-stijl setups bijna altijd het geval is — worden die tokens bij herstart niet opnieuw verrekend. Bij intensief gebruik liggen de besparingen in de orde van 40-60% op context-tokens.

De **OpenAI-compatible proxy** is een interessante toevoeging: tools zoals Aider of Cline kunnen via deze proxy Hermes als backend gebruiken, inclusief geabonneerde services. Dat maakt Hermes een router die bestaande tooling hergebruikt zonder volledige migratie. LSP semantic diagnostics worden nu getriggerd bij file writes: directe type-error detectie in de agentic loop, vergelijkbaar met de security-guidance plugin in Claude Code.

22 platforms worden ondersteund, waaronder de nieuwe toevoegingen xAI Grok (1M context) en LINE Messaging API.

## Open Source Tools — Microsoft Build 2026: MAI-Thinking-1 en MAI-Code-1-Flash

Microsoft kondigde op Build 2026 (2 juni) twee eigen frontier modellen aan die de competitive landscape verder compliceren.

**MAI-Thinking-1** (1 biljoen parameters) is Microsofts eerste eigengebouwde reasoning-model — gepositioneerd als directe concurrent voor o3 en Claude Opus 4.8 op STEM-reasoning benchmarks. Parameters zijn indicatief: de architectuur is nog niet volledig gedocumenteerd, maar de positionering als o3-concurrent geeft aan dat Microsoft de reasoning race niet meer aan derden overlaat. Voor teams die nu Opus 4.8 evalueren voor zware reasoning-taken, is MAI-Thinking-1 zodra de API beschikbaar is een benchmark-kandidaat.

**MAI-Code-1-Flash** (137B parameters) richt zich op lage latency voor coding context, specifiek voor GitHub Copilot-integratie in VS Code en Codespaces. Schaalverschil met MAI-Thinking-1 is aanzienlijk: Flash richt zich op snelheid in de IDE, niet op diep redeneren. De opdeling Flash/Thinking spiegelt de Sonnet/Opus-architectuurkeuze bij Anthropic.

**Copilot Studio** integreert nu als visuele agent-bouwer in VS Code en GitHub Codespaces, met support voor Python, C# en TypeScript. De workflow designer biedt multi-step agent orchestratie zonder low-level SDK-code — vergelijkbaar in scope met wat Anthropic aanbiedt via de agent SDK, maar dan visueel en tight geïntegreerd in de GitHub-omgeving.

GitHub Copilot stapt over op usage-based billing via AI Credits: per gebruik, niet meer vast abonnement, met user-level budgets en een Copilot Max upgrade-pad. Voor engineering teams die Copilot heavy gebruiken, verschuift budgetbeheer van teamplan naar per-developer granulariteit — dezelfde beweging die Uber vorige week tot een $1.500-cap dreef.

## Tot slot

De `/goal` feature in Claude Code trekt een lijn die steeds scherper wordt: de developer definieert het resultaat, het model bouwt het pad. Gecombineerd met `claude agents` multi-session view en Auto Mode Pro ontstaat een werkstijl die fundamenteel verschilt van prompt-response. De vraag die na deze week blijft hangen: wanneer is dit paradigma productierijp voor Orion-stijl deployments — met alle bijbehorende observability, kostenbeheer en rollback-garanties die je dan nodig hebt?
