Drie technische verschuivingen deze week die direct raken aan hoe autonome workflows gebouwd worden. Opus 4.8 herintroduceert orchestratie-aan-model-zijde met Ultracode: Claude schrijft de JS-orchestratiescripts zelf en stuurt honderden parallelle subagents aan in één sessie. De MCP Release Candidate voert de grootste revisie door het protocol ooit door: sessions zijn weg, load balancers worden trivial. En Headroom haalt 60-95% van je tokens eraf vóórdat ze het LLM bereiken — als MCP server, proxy, of Python library.

De rode draad: de infra-laag onder agentic workflows wordt dit jaar structureel goedkoper, sneller en eenvoudiger te schalen. Elk van de drie items hieronder vraagt een concrete actie.

## Claude Code — Opus 4.8 met Ultracode en Dynamic Workflows

Claude Opus 4.8 is op 28 mei GA gegaan op dezelfde prijs als 4.7: $5/$25 per miljoen tokens input/output. Fast Mode met Opus 4.8 kost $10/$50 MTok voor 2,5× snelheid. De prijs is gelijk; de capaciteit is niet gelijk.

De twee nieuwe functies zijn Ultracode en Dynamic Workflows, en ze zijn ontworpen als paar:

**Ultracode** is een Claude Code-instelling — geen apart model — die `xhigh effort` activeert én model-side orchestratie aanzet. In de praktijk schrijft Claude voor complexe taken een JavaScript-orchestratiescript vóór hij begint, voert dat script uit via de Agent SDK, en maakt subagents aan op basis van wat het script vereist.

**Dynamic Workflows** is het uitvoeringsraamwerk daaronder. Het draait honderden parallelle subagents in één sessie voor taken die te groot zijn voor één conversatiecontext. De workflows zijn de JS-scripts die Ultracode schrijft — Claude bepaalt de granulering en het aantal parallelle agents zelf.

```javascript
// Voorbeeld van wat Dynamic Workflows genereert voor een codebase-audit
const tasks = sourceFiles.map(file => ({
  type: 'agent',
  prompt: `Audit ${file} for security vulnerabilities`,
  tools: ['read_file', 'search_codebase']
}));
await Promise.all(tasks.map(t => sdk.runAgent(t)));
```

Twee kleinere updates die de dagelijkse cyclus versnellen: plugins in `.claude/skills/` worden nu automatisch geladen bij opstarten, en `/reload-skills` herscant de directory zonder herstart. Dit comprimt de iterate-test-iterate loop voor plugin-ontwikkeling aanmerkelijk.

**Concrete toepassing:** Ultracode is de juiste instelling voor codebase-brede migraties waarbij je normaal taken zou opdelen over meerdere sessies: TypeScript-upgrades, dependency-audits, security scans. Voor Orion is Dynamic Workflows direct bruikbaar — één JS-script stuurt tientallen parallelle subagents aan en levert resultaten terug als gestructureerde output. De security-guidance plugin die elke file-edit controleert op vulnerabilities is nuttig in productiecodebases waar je de menselijke reviewcyclus wil inkorten.

## Claude Code — MCP Release Candidate: stateless servers, Tasks en MCP Apps

De release candidate voor de MCP-spec van 2026-07-28 is beschikbaar — de grootste revisie van het protocol sinds lancering. Drie wijzigingen zijn architectureel significant:

**Stateless servers.** De `Mcp-Session-Id` header vervalt. MCP-servers hoeven geen session-state meer bij te houden. Load balancers routen requests op de `Mcp-Method` header zonder body-inspectie en zonder sticky sessions. Dit elimineert de Redis- of in-memory store die de meeste productie-MCP-servers nu nog vereisen.

**Extensions-laag.** De spec introduceert een formeel extensiemechanisme, direct gevuld met twee extensies:
- `Tasks`: voor langlopende werkstromen met progress-callbacks — het protocol-equivalent van een background job die terugrapporteert aan de client
- `MCP Apps`: server-rendered UIs zichtbaar in de host-client, inclusief Claude Code — servers kunnen nu visuele interfaces pushen naar de tool-host

**OAuth/OIDC-conforme autorisatie** vervangt de ad-hoc token handling die servers nu zelf implementeren. W3C Trace Context in `_meta` (traceparent, tracestate, baggage) wordt standaard voor distributed tracing over multi-agent chains.

```python
# Na de RC: geen session management meer nodig in je MCP server
@server.call_tool()
async def handle_tool(name: str, arguments: dict) -> list[types.TextContent]:
    # Elke request is volledig zelfstandig — geen session_id, geen state lookup
    result = await process(name, arguments)
    return [types.TextContent(type="text", text=result)]
```

De SDK-planning is strak: Tier 1 SDKs (Python, TypeScript) moeten binnen een 10-weken-window support shippen.

**Concrete toepassing:** Nu is het moment om bestaande MCP-servers te reviewen op session-afhankelijkheid. Servers die state bijhouden in Redis of in-memory stores kunnen na de RC versimpeld worden tot pure request-handlers. De Tasks-extensie is direct bruikbaar voor langlopende Orion-jobs die nu ofwel polling vereisen ofwel websockets. MCP Apps openen de mogelijkheid tot server-rendered dashboards zichtbaar in Claude Code — een patroon dat de grens tussen CLI-tool en web-UI vervaagt.

## Open Source Tools — Headroom: 60-95% tokenreductie als MCP server

Headroom is deze week één van de snelst groeiende Python-repos op GitHub (+13.308 sterren in zeven dagen). Het is een open-source context compression layer die tool outputs, logs, RAG-chunks, bestanden en conversatiegeschiedenis comprimeert vóór ze het LLM bereiken. Het compressiepercentage — 60-95% afhankelijk van content-type — is reversibel via het CCR-protocol.

**CCR (Compression with Conditional Retrieval)** werkt als volgt: Headroom comprimeert grote blokken naar compacte referenties en slaat de originelen op in een lokale store. Als het LLM een referentie wil uitbreiden, doet het een tool call die de originele content ophaalt. Vanuit het perspectief van de context window ziet het model een samenvatting totdat het specifiek meer detail nodig heeft.

Installatievormen:

```bash
# Als MCP server in Claude Code (.claude/mcp.json)
headroom serve --port 8080

# Als transparante proxy om bestaande tools heen
headroom wrap claude
headroom wrap codex

# Als Python library
pip install headroom[compression]
```

De MCP server mode is het relevantst voor Claude Code gebruik: voeg Headroom toe als MCP server en alle tool outputs worden automatisch gecomprimeerd vóór ze in de context terechtkomen. De client hoeft niets te weten van de compressie; het werkt transparant achter de aanroep.

**Concrete toepassing:** Direct relevant voor sessies met veel file reads, log outputs, of grote RAG-chunks. Anthropic's factureringswijziging per 15 juni maakt tokenbesparing een directe kostenpost. Headroom als MCP server in `.claude/mcp.json` is vijf minuten configuratie voor potentieel significante factuurreductie bij intensieve Claude Code-gebruikers. De proxy-mode (`headroom wrap claude`) werkt ook zonder enige configuratiewijziging in bestaande scripts.

## AI Builders — Simon Willison: micropython-wasm als sandbox voor agentic code execution

Simon Willison publiceerde gisteren een update over `micropython-wasm` als sandboxprimitief voor agentic plugins. De aanpak: MicroPython gecompileerd naar WebAssembly als plugin interface voor Datasette Agent, zodat user-provided code uitgevoerd kan worden zonder container-overhead en zonder server-side risico.

Het mechanisme is clean: een WASM-runtime heeft geen netwerktoegang, geen filesystem access buiten de geconfigureerde mounts, en geen shared state met de host. Er is geen Docker daemon, geen seccomp-configuratie, geen VM. De WASM boundary is de security boundary.

```javascript
// Willison's patroon: WASM module als plugin executor
const wasm = await WebAssembly.instantiate(micropython_wasm, imports);
const result = wasm.exports.run_code(user_python_string);
// Geen netwerk, geen filesystem, geen escape buiten de sandbox
```

Willison implementeert dit als alpha-package met een Claude Code plugin interface — vergelijkbaar met wat Anthropic nu standaard ondersteunt via `/reload-skills`. De combinatie van WASM-sandbox en Claude Code's plugin-systeem toont hoe je snel agentic code execution kunt prototypen zonder productie-infra op te tuigen.

De observatie loopt parallel aan wat op Code w/ Claude 2026 (mei) naar voren kwam: verhoogde rate limits voor Pro/Max/Enterprise en de verschuiving naar multi-agent orchestratie creëren meer druk op veilige code execution patterns. WASM is één antwoord; Managed Agents (Google) en Dynamic Workflows (Anthropic) zijn andere — elk met een andere balans tussen controle en beheerde infra.

## Tot slot

De drie items van vandaag convergeren op één vraag: waar leg je de grens tussen wat de agent autonoom doet en wat je zelf controleert? Ultracode en Dynamic Workflows schuiven die grens verder van je af — Claude schrijft de orchestratie. De MCP RC maakt de infra daaronder eenvoudiger. Headroom maakt de kosten van grootschalige tool-calls behapbaar. Willison's WASM-sandbox suggereert dat de beveiliging van die autonomie ook eenvoudiger kan worden.

Zodra Dynamic Workflows honderden subagents parallel draait, hoe valideer je dat de orchestratie doet wat je bedoelt — en niet iets wat er op lijkt?
