Per 15 juni 2026 verandert Anthropic de billing voor alle programmatische agent-toegang fundamenteel. Wie nu `claude -p` draait in scripts, agents via de GitHub Actions runner laat lopen of third-party agent tooling gebruikt, betaalt straks per token via een apart maandelijks credit budget — niet meer als onderdeel van het flat-rate subscription. Dat is de grootste prijswijziging voor agent-gebruikers seit de introductie van Claude Code.

Tegelijkertijd rijpen twee aparte ecosystemen verder: OpenAI lanceert GPT-5.5 Instant met een asynchroon memory-aging mechanisme dat interessante vragen stelt over agent state management, en Simon Willison brengt een WASM-gebaseerde Python sandbox als alpha die container-vrije code execution belooft voor agents.

## Claude Code — Agent SDK billing-split per 15 juni 2026

Wat er verandert: de volgende tooling wordt per 15 juni 2026 uit het flat-rate subscription gehaald en metered op volledige API-tarieven:

- `claude -p` (non-interactive modus)
- Claude Code GitHub Actions runner
- Agent SDK (python/typescript)
- Third-party agents die via jouw account draaien

Wat blijft: interactieve Claude.ai chat en terminal Claude Code sessies (`claude` zonder `-p`) blijven op het huidige abonnement.

De credit budgets per plan:
- **Pro**: $20/maand
- **Max 5x**: $100/maand
- **Max 20x**: $200/maand

Credits rollen niet over en als het budget op is stopt SDK-gebruik volledig — tenzij je expliciet usage credits als backstop hebt ingeschakeld. De achterliggende reden is transparant: subscriptions subsidieerden agent-gebruik tot 30× goedkoper dan directe API-tarieven. Voor heavy agent-gebruikers is dit een significante kostenstijging.

**Actielista voor voor 15 juni:**

1. Claim de eenmalige opt-in via je Claude account settings (zonder opt-in geen SDK-toegang na de deadline)
2. Inventariseer elk script of workflow dat `claude -p` gebruikt — dit zijn de meest token-intensieve kandidaten
3. Voeg output caching toe aan repetitieve `claude -p` calls: zelfde systeemprompt + gelijke input = 90% cache hit rate mogelijk
4. Overweeg usage credits als backstop voor productie-agents zodat ze niet hard stoppen bij budgetlimiet
5. Zet token logging op per workflow om verbruik te volgen vanaf dag 1

```bash
# Token-verbruik monitoren via claude -p
claude -p "Analyseer deze diff: $(git diff HEAD~1)" \
  --output-format json | jq '{tokens: .usage, cost_estimate: (.usage.input_tokens * 0.000003 + .usage.output_tokens * 0.000015)}'
```

Concreet voor Orion-workflows: als agents geregeld lange code reviews doen via SDK, is dit het moment om te calculeren of een lokaal model voor de eerste-pass filter goedkoper uitvalt dan elke review via API te laten lopen. De 30×-subsidie verdwijnt — de architectuurkeuzes die daardoor slim leken, verdienen herziening.

## Claude Code — security-guidance plugin en fallback models

Naast de billing-wijziging krijgt Claude Code een nieuwe native security-guidance plugin. De plugin draait twee passes bij elke code-edit sessie:

1. **Patroon-scan** per edit: snelle statische analyse op bekende kwetsbaarheidssignaturen (SQL injection, hardcoded credentials, insecure deserialization, SSRF patterns)
2. **Model review** aan het einde van elke turn: volledig model-review van de accumulated changes in die turn

De plugin is configureerbaar via `settings.json`:

```json
{
  "plugins": ["security-guidance"],
  "security": {
    "scanOnEdit": true,
    "fullReviewPerTurn": true,
    "severity": "medium"
  }
}
```

Wat dit concreet betekent: security review zit nu in de inner loop van development, niet als apart reviewmoment achteraf. Voor Orion-projecten die externe input verwerken is dit een directe waarde-toevoeging zonder extra tooling.

Tevens toegevoegd: **fallback models** — als het primaire model onbeschikbaar is, valt Claude Code terug op een geconfigureerde fallback zonder de sessie te onderbreken. En uitgebreide glob-support voor deny rules zodat je preciezer kunt bepalen welke bestanden en paden de agent niet mag aanraken.

## OpenAI — GPT-5.5 Instant en dreaming memory

GPT-5.5 Instant vervangt GPT-5.3 Instant als standaard ChatGPT-model. De technische verbeteringen — betere STEM/coding accuratesse, native writing en coding blocks in de UI — zijn incrementeel. Interessanter is de nieuwe memory-architectuur.

**Dreaming** is een asynchroon background process dat bestaande memories automatisch bijwerkt als temporele context verouderd raakt. Voorbeeld: als een memory bestaat "Je vliegt volgende week naar Singapore" en die datum is verstreken, markeert het systeem de memory automatisch als historisch — "Je was in juli 2026 in Singapore" — zonder user intervention. GPT-4.5 wordt retired per 27 juni 2026.

Het dreaming-patroon is architectureel interessant voor agent memory design: in plaats van een statische memory store die veroudert, heb je een decay/aging process dat temporele feiten corrigeert. Het meest directe MCP-equivalent zou een tool zijn die periodiek een set memories evalueert op temporele geldigheid:

```python
# Concept: memory aging als MCP tool
async def age_memories(memories: list[Memory]) -> list[Memory]:
    now = datetime.utcnow()
    for memory in memories:
        if memory.expires_at and memory.expires_at < now:
            memory.text = await reframe_as_past(memory.text, memory.expires_at)
            memory.is_historical = True
    return memories
```

Of jullie huidige Claude Code agent memory hier baat bij heeft hangt af van hoeveel tijd-gebonden feiten je opslaat — voor een project-tracker agent met deadlines is het patroon relevant.

## AI Builders — Simon Willison's micropython-wasm

Simon Willison publiceerde `micropython-wasm` als alpha package (6 juni): een WebAssembly-gebaseerde Python sandbox gebouwd als plugin voor Datasette Agent. Het kernidee: code execution in agents zonder Docker of container-dependency, via MicroPython gecompileerd naar WASM.

Voordelen ten opzichte van Docker-sandboxes:
- Geen container runtime vereist — draait direct in het host process
- WASM memory isolation als security boundary (deterministic execution)
- Laag memory footprint — relevant bij agent orchestration met veel parallelle workers

```python
# Gebruik micropython-wasm als MCP tool (concept)
from datasette_agent_micropython import MicropythonSandbox

sandbox = MicropythonSandbox(max_memory_mb=32)
result = await sandbox.execute(code=user_code, timeout_ms=5000)
```

De beperkingen zijn reëel: MicroPython ondersteunt niet de volledige CPython stdlib — geen `requests`, beperkte `asyncio`, geen C-extensions. Voor pure data-transformatie of eenvoudige berekeningen voldoet het; voor complexe agent tools met externe calls heb je toch een volwaardige sandbox nodig.

Willison analyseert in dezelfde periode Uber's cost-cap aanpak als kostenbeheersingspatroon — extra relevant nu Anthropic's Agent SDK billing verandert. Het idee: stel harde tokenlimieten per werktype in, niet per request, zodat een ontspoorde agent-loop niet het volledige maandbudget consumeert.
