Vandaag is een volle dag voor agent-architectuur. Terwijl in Bengaluru het MCP Dev Summit loopt en de 2026-07-28 release candidate van het protocol stateless wordt verklaard, verschijnen op drie fronten tegelijk implementeerbare updates: Claude's Dynamic Workflows, Gemini Managed Agents en Microsoft CodeAct. Elk pakken hetzelfde kernprobleem aan vanuit een andere hoek: hoe combineer je parallelle uitvoering met betrouwbare isolatie zonder dat de orchestratie-overhead de taak zelf overschaduwt?

Wat opvalt is dat de drie systemen convergeren op vergelijkbare abstracties. Een orchestrator genereert een plan als code, workers voeren dat plan uit in geïsoleerde sandboxes, en de orchestratie-laag beheert state en scheduling. De details — wie het plan schrijft, welke VM het uitvoert, hoe state bijgehouden wordt over calls heen — zijn de echte differentiator.

## Claude Code — Dynamic Workflows orkestreert honderden subagenten via een Python-script

Claude Dynamic Workflows (research preview) is een fundamenteel andere aanpak dan statische multi-agent setups. In plaats van dat je vooraf een vaste pipeline configureert, schrijft Claude zelf een Python-orkestratiescript dat de workflow definieert. De harness voert dat script uit en schaalt subagenten automatisch op basis van de beschikbare compute.

De architectuur: Dynamic Workflows genereren een Python-script dat `call_agent()` gebruikt om subagenten aan te sturen. De harness handelt worker scheduling en parallelisatie af — het script definieert alleen het *wat*, niet het *hoe* van de uitvoering. Dit maakt het mogelijk om per taak een optimale topologie te genereren in plaats van één generieke pipeline te hergebruiken voor elke taak.

Concreet gebruik in Claude Code:

```bash
# In Claude Code, met /effort xhigh ingeschakeld
/effort xhigh
"Analyseer onze gehele TypeScript codebase op security vulnerabilities,
 genereer per module een gedetailleerd rapport, en combineer tot een executive summary"
```

Claude genereert dan een Dynamic Workflow-script dat de codebase opsplitst in modules, per module een subagent spawnt voor analyse, en de resultaten aggregeert in een finale synthesepass. Het verschil met handmatige parallelisatie via losse subagent calls: het orkestratiescript is zelf een artifact dat je kunt opslaan, reviewen en aanpassen voor hergebruik.

Activeer Dynamic Workflows via het research preview menu in Claude Code settings. Gebruik `/effort xhigh` voor taken waarbij Claude significant meer reasoning moet inzetten voor het genereren van het orkestratiescript zelf — de kwaliteit van het script bepaalt de kwaliteit van de uiteindelijke output.

## Gemini — Managed Agents in public preview met server-side sandbox-isolatie

Gemini Managed Agents zijn nu in public preview via de Gemini API: stateful, autonome agents die draaien in geïsoleerde Google-hosted Linux-sandboxen. De agent loop draait volledig server-side, inclusief plannen, code schrijven, uitvoeren en browsen. Je hoeft geen eigen agent harness te bouwen — Google beheert de state en de sandbox lifecycle.

De Antigravity Agent is de reference implementation: een agent die zelfstandig bestanden beheert, code uitvoert en web-browst zonder dat er client-side orchestratie nodig is.

```python
from google.generativeai import ManagedAgent

agent = ManagedAgent(
    model="gemini-3.5-flash",
    tools=["code_execution", "web_browse", "file_management"]
)
result = await agent.run(
    "Analyseer de Q1 sales data in /data/ en genereer een markdown rapport"
)
```

Gemini 3.5 Flash is tegelijkertijd GA gegaan als het meest capabele model voor agentic en coding taken in de Gemini-family. Belangrijk aandachtspunt: Google verwijderde op 8 juni het legacy Interactions API schema. De `outputs`→`steps` rename is nu live. Bestaande Gemini API integrations die nog op het oude schema draaien moeten direct migreren — dit is geen deprecated-maar-nog-werkend scenario.

## Open Source Tools — MCP Dev Summit Bengaluru en de stateless protocol RC

Het MCP Dev Summit vindt vandaag en morgen (9-10 juni) plaats in Bengaluru. De timing valt samen met de publicatie van de release candidate voor MCP spec 2026-07-28, waarvan de headline change de verschuiving naar een stateless protocol-laag is.

Wat stateless MCP betekent in de praktijk: session-state verplaatst van de protocol-laag naar de applicatielaag. MCP-servers worden daardoor horizontaal schaalbaarder — je kunt meerdere instances achter een load balancer draaien zonder sticky sessions. Voor enterprise MCP deployments is dit een fundamentele vereenvoudiging van de infrastructure requirements. Horizontale scaling, zero-downtime deploys en multi-region setups worden triviaal in plaats van een aparte engineering uitdaging.

De 10-weeks validatieperiode voor SDK-maintainers loopt tot begin augustus. Actiepunten nu:

- RC spec doorlezen en eigen MCP-server implementations testen op state-assumptie
- Servers die session-state impliciet in de protocol-laag aanhouden identificeren en migreren naar applicatielaag
- Dev Summit presentaties volgen voor migratiepatronen en best practices

Het ecosysteem heeft intussen een schaal bereikt waarbij spec-changes significant zijn: 10.000+ publieke MCP-servers en 164 miljoen maandelijkse PyPI downloads voor de Python SDK.

## AI Builders — Microsoft CodeAct bij BUILD 2026: tool-calls als één Python-programma

Microsoft presenteerde op BUILD 2026 CodeAct als onderdeel van hun Agent Framework: in plaats van sequentiële tool-calls (N × model call + N × tool call) schrijft het model één Python-programma dat alle tools aanroept via `call_tool()`. Dat programma draait in een Hyperlight micro-VM en geeft één geconsolideerd resultaat terug.

```python
# CodeAct pattern — dit Python-programma genereert het model
result_a = call_tool("search", {"query": "MCP stateless spec changelog"})
result_b = call_tool("read_file", {"path": "mcp_server.py"})
summary = call_tool("summarize", {"text": f"Spec: {result_a}\nCode: {result_b}"})
return summary
```

De winst is één model round-trip in plaats van N. `agent-framework-hyperlight` (alpha) biedt process-level sandbox-isolatie per tool-call via Hyperlight micro-VM's, wat sterke isolatie gratis meegeeft op het granulariteitsniveau van één tool-execution.

Vergelijk dit met Claude's Dynamic Workflows: beide reduceren model round-trips, maar via verschillende mechanismen. CodeAct via één uitvoerbaar Python-programma per agent-stap. Dynamic Workflows via een orchestratiescript dat de shape van de gehele workflow definieert en subagenten aanstuurt over een langere taak.

Simon Willison analyseert tegelijkertijd Microsoft's nieuwe eigen frontier modellen: MAI-Thinking-1 (1T totale parameters, 35B actief via sparse MoE, reasoning model) en MAI-Code-1-Flash (137B totaal, 5B actief, purpose-built voor GitHub Copilot en VS Code). Microsoft claimt dat MAI-Thinking-1 Sonnet 4.6 overtreft in blind evaluaties. Of die claim standhoudend is bij onafhankelijke benchmarks is nog te zien, maar MAI-Code-1-Flash als goedkoop alternatief voor coding-specifieke inference in VS Code-gebaseerde workflows is het testen waard.

## Tot slot

Dynamic Workflows, Managed Agents en CodeAct zijn drie antwoorden op dezelfde vraag: hoe vermijd je dat orchestratie-overhead duurder wordt dan de taak zelf? Het interessante is niet welke aanpak wint — het is dat alle drie nu in testbare preview beschikbaar zijn. De MCP Dev Summit vandaag is het uitgelezen moment om te kijken hoe een stateless protocol-laag past bij server-side agent loops die inherent state nodig hebben.
