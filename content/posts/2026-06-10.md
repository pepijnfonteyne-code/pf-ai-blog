Drie releases die elk een concreet pijnpunt aanpakken. `--safe-mode` in Claude Code v2.1.170 lost het "welk onderdeel van mijn configuratie veroorzaakt dit?" probleem op zonder een schone installatie. Gemini 3.5 Flash GA bereikt een MCP Atlas-score van 83,6% en profileert zich daarmee als serieuze tweede kandidaat in multi-model pipelines. Codex breidt Computer Use uit naar Windows en voegt een CLI-to-Desktop handoff toe die de kloof tussen terminal en GUI sluit.

Elk van de drie lost iets op dat vroeg of laat opduikt: configuratie-ruis bij troubleshooten, modelkeuze voor kostengevoelige subtasks, en platform-overstijgende agent-automatisering.

## Claude Code — v2.1.170: Safe Mode, /cd en disableBundledSkills

Release v2.1.170 van 9 juni bevat drie onafhankelijke toevoegingen die elk een ander deel van de configuratie-stack aanpakken.

**`--safe-mode`** start Claude Code zonder CLAUDE.md, plugins, skills, hooks en MCP-servers in één flag. Het is de snelste manier om vast te stellen of onverwacht gedrag in de configuratie zit of in de baseline CLI:

```bash
claude --safe-mode
```

In complexe setups zoals Orion — waarbij meerdere CLAUDE.md-bestanden, custom hooks en externe MCP-connectors actief zijn — was het isoleren van problematisch gedrag eerder een kwestie van componenten één voor één uitcommentariëren. `--safe-mode` geeft een reproduceerbare baseline zonder de actieve configuratie aan te raken. Als referentiepunt bij het rapporteren van bugs: je kunt bevestigen of het probleem buiten de baseline-stack zit voordat je een issue opent.

**`/cd [directory]`** verplaatst de actieve sessie naar een andere werkmap zonder de bestaande prompt-cache te invalideren. In een monorepo waarbij je van frontend naar backend naar infra navigeert, bewaart dit alle eerdere tool-call-resultaten en context die al getokeniseerd zijn. De werkmap-context wordt vervangen, maar de sessie-state blijft intact — merkbaar verschil in tokenkosten bij lange sessies met veel tool-output.

**`disableBundledSkills`** in settings.json verbergt de ingebouwde slash-commands van het model. Dit is relevant wanneer je een custom-only command-set wilt aanbieden:

```json
{
  "disableBundledSkills": true
}
```

De instelling voorkomt dat built-in skill-definities de model-context opvullen. Als je custom skills bouwt voor specifieke workflows — dedicated Orion-commands of domein-specifieke tools — geeft dit ruimte die anders wordt ingenomen door builtin-definities die je toch niet gebruikt.

De combinatie van de drie features is wat telt: `--safe-mode` voor reproduceerbare isolatie, `/cd` voor sessie-persistentie bij mapwisseling, en `disableBundledSkills` voor een schone command-set. Drie gerichte verbeteringen die de dagelijkse workflow raken zonder nieuwe abstracties te introduceren.

## Gemini — 3.5 Flash GA en Managed Agents API in Public Preview

Gemini 3.5 Flash is nu algemeen beschikbaar als Google's primaire model voor agentic en coding-taken op Flash-latentie. De benchmark-cijfers zijn relevant omdat ze direct vergelijkbaar zijn met MCP-heavy setups:

| Benchmark | Score |
|-----------|-------|
| Terminal-Bench 2.1 | 76,2% |
| GDPval-AA | 1656 Elo |
| MCP Atlas | 83,6% |

De MCP Atlas Benchmark (83,6%) meet specifiek de capaciteit om MCP-tool-calls correct te sequentiëren in complexe agentic scenario's — een directe kwaliteitsmeting voor hoe goed een model presteert in het type workflows dat wij dagelijks draaien. Gemini 3.5 Flash overtreft Gemini 3.1 Pro op alle drie de metrics, terwijl de latentie op Flash-niveau blijft.

Parallel lanceerde Google **Managed Agents** in de Gemini API in public preview: een serverless runtime voor stateful agents in geïsoleerde Google-hosted Linux sandboxes, met session state beheerd via de Interactions API:

```python
from google import genai

client = genai.Client()
session = client.agents.create_session(
    model="gemini-3.5-flash",
    tools=[tool_1, tool_2]
)
response = session.send_message("Analyseer de productie-logs van gisteren")
# Sessie-state blijft behouden over calls heen
next_response = session.send_message("Vergelijk met vorige week")
```

De sandbox-isolatie is vergelijkbaar met wat E2B of Modal bieden voor code-execution, maar dan specifiek voor stateful agent-workloads. Het serverless model elimineert de infra-overhead van eigen session-state-management.

Praktische afweging: Gemini 3.5 Flash als secundair model in een multi-agent setup is het meest interessant voor kostengevoelige subtasks waarbij Claude gereserveerd wordt voor primaire redenering. De MCP Atlas-score (83,6% vs Claude's dominantie op dit type benchmark) maakt het een serieuze optie voor MCP-tool-calling subtasks in hybride pipelines. Managed Agents is minder urgent voor setups die eigen infra draaien, maar het session-API-patroon is een bruikbaar referentie-design.

## OpenAI — Codex Computer Use op Windows en /app Desktop Handoff

Codex breidt twee bestaande features significant uit.

**Computer Use op Windows** gebruikt de Windows Accessibility API en GDI-schermcapture voor native Windows desktop-interactie. Tot nu toe was Computer Use in de Codex-omgeving beperkt tot macOS via Quartz/Core Graphics. De Windows-implementatie brengt dezelfde agent-capabilities — applicaties zien, klikken, typen — naar Windows-omgevingen. Dit is relevant voor CI-pipelines die GUI-gebaseerde Windows-applicaties testen, of voor automatisering van Windows-specifieke enterprise-tooling.

**`/app`-command in de Codex CLI** geeft een actieve terminal-thread door aan Codex Desktop (macOS of native Windows) zonder de conversatie-state te verliezen:

```bash
# Middenin een debugging-sessie in de Codex CLI:
/app
# → Opent Codex Desktop met de volledige sessie-context overgenomen
```

De handoff behoudt de volledige sessiehistorie en context zonder re-tokenisatie — de CLI-thread wordt niet onderbroken of opnieuw opgebouwd. Dit is nuttig wanneer je een actieve Codex-sessie wilt visualiseren voor iemand die niet in de terminal werkt: de context komt mee, de GUI laat de output zien.

Als vergelijkingspunt voor de Claude Code-stack: `/app` adresseert de CLI→GUI transitie die Claude Code momenteel niet heeft. `--safe-mode` en `/cd` in Claude Code v2.1.170 pakken overlappende workflow-problemen aan — configuratie-isolatie en sessie-persistentie — maar via andere mechanismen. De `/app` handoff is een patroon dat interessant wordt naarmate meer werk via remote sessions gaat en visuele output relevant wordt voor samenwerking.

## Tot slot

`--safe-mode` is het soort feature dat je pas waardeert op het moment dat je het nodig hebt — en dan wens je dat het er al jaren was. Dat het in dezelfde release zit als `/cd` en `disableBundledSkills` suggereert dat Anthropic systematisch de friction-punten aanpakt in complexe multi-config setups. De vraag is of de volgende stap iets is als een `--safe-mode` variant die selectief slechts één laag isoleert — alleen MCP-servers, of alleen hooks — in plaats van alles tegelijk.
