De meest ingrijpende verandering van deze week is stilletjes binnengekomen: MCP gaat stateless. Geen `Mcp-Session-Id` header meer, geen `initialize`-handshake, gewoon plain HTTP achter een load balancer. De finale spec is 28 juli — dat is de harde datum in deze update, en wie custom MCP-servers heeft runt de audit beter nu dan dan.

Tegelijk schaalt Claude Code zijn agent-architectuur omhoog met ultracode en 5-laags nesting, en brengt Nous Research met Hermes Agent een praktisch referentiemodel voor zelf-verbeterende agent-loops op open-source hardware. Drie bewegingen die elk iets oplossen wat eerder handmatige orchestratiecode of cloud-afhankelijkheid vereiste — en elk direct toepasbaar is in de workflows die we op Orion draaien.

## Claude Code — ultracode en nested sub-agents tot 5 lagen diep

Claude Code introduceert twee gerelateerde uitbreidingen die samen de schaal van agentic workflows substantieel vergroten.

De eerste is **ultracode**: een Claude Code-specifieke instelling — geen model effort level — die xhigh effort naar het model stuurt én Claude automatisch laat beslissen wanneer het een multi-agent workflow opstart. Het is een hernoeming van het vorige `workflow`-keyword; wie dat al gebruikte als trigger schakelt gewoon over op de nieuwe naam. Het verschil met gewone xhigh effort: ultracode combineert die effort-instelling met dynamische workflow-orchestratie, zodat Claude op eigen initiatief beslist of een taak opsplitst in parallelle subtaken.

De tweede uitbreiding is **nested sub-agents tot 5 lagen diep**. Een root-agent kan sub-agents aanmaken die zelf opnieuw sub-agents spawnen, tot maximaal 5 niveaus. Dat maakt parallelle decomposities mogelijk zonder handgeschreven orchestratiecode:

```
root-agent (planning)
├── level-2: module A           ← parallel met module B
│   ├── level-3: bestand A1
│   └── level-3: bestand A2
└── level-2: module B
    ├── level-3: bestand B1
    └── level-3: bestand B2
```

Rate limits zijn verdubbeld, en Opus 4.8 is de nieuwe standaard voor Claude Code-sessies. Bijkomend effect: lange agentic sessies lopen minder snel tegen rate-limit-muren aan, wat vooral merkbaar is bij uitgebreide Orion-runs.

De combinatie ultracode + 5-laags nesting is het meest waardevol voor taken die van nature decomponeerbaar zijn: grote refactors over meerdere modules, multi-repo analyses, of taken waarbij planning en uitvoering parallel kunnen schalen. De hiërarchie ontwerpen blijft handwerk — een root-agent die ongestructureerd sub-agents spawnt zonder context-grenzen bereikt snel de limiet. Maar de plumbing om dat hiërarchisch te structureren is nu native aanwezig: root-agent voor planning, level-2 per module, level-3 per bestand is een werkend patroon zonder extra orchestratiecode.

## Open Source Tools — MCP 2026 RC: sessions en handshake verdwijnen

De MCP 2026 Release Candidate (finale spec 28 juli) is de meest ingrijpende revisie van het protocol since de lancering. Twee breaking changes domineren:

- **`Mcp-Session-Id` header** wordt verwijderd (SEP-2567)
- **`initialize` / `initialized` handshake** verdwijnt (SEP-2575)

MCP-servers draaien voortaan als plain stateless HTTP. Geen sticky sessions, geen shared session stores, geen speciaal routing — gewoon round-robin load balancing achter een standaard HTTP-proxy. Remote MCP-deployments worden na migratie aanzienlijk eenvoudiger te beheren: geen session-aware infrastructure meer nodig.

Nieuw erbij: `tools/list`, `resources/list` en `resources/read` responses krijgen `ttlMs` en `cacheScope` velden voor client-side caching.

```json
{
  "tools": [...],
  "cacheControl": {
    "ttlMs": 300000,
    "cacheScope": "session"
  }
}
```

De RC introduceert ook een Extensions-framework met **MCP Apps** (server-rendered UIs vanuit een MCP-server), een **Tasks-extensie** voor langlopende processen, en OAuth/OIDC-gebaseerde authorization hardening. Sampling en Roots zijn deprecated met een migratiepad dat in de RC-docs beschreven staat.

De actie voor nu: audit alle custom MCP-servers op gebruik van `Mcp-Session-Id` en de `initialize`-handshake vóór 28 juli. De `ttlMs` caching reduceert `tools/list` calls direct in high-throughput agent pipelines — dat is dag-één-winst na de migratie, zonder verdere aanpassingen.

### Headroom: token-compressie als MCP-server

Aanvullend op de MCP-infrastructuurkant: **Headroom** is een open-source compressielaag die als MCP-server wordt geëxposed en tool outputs, RAG-chunks, logs en code comprimeert voordat ze het model bereiken. Deze week op #2 van GitHub Trendshift. Benchmarks: 92% reductie op code search (17.700 → 1.400 tokens), SRE-debugging van 65.694 → 5.118 tokens zonder kwaliteitsverlies.

De architectuur heeft drie componenten:
- **ContentRouter** — detecteert automatisch content-type
- **SmartCrusher** — voor JSON-compressie
- **CodeCompressor** — AST-aware code-compressie die structuur bewaart

Als MCP-server exposed Headroom drie tools: `headroom_compress`, `headroom_retrieve` en `headroom_stats`. CCR (Reversible Compression) houdt de raw data lokaal op de server; het model haalt die op via `headroom_retrieve` wanneer het de volledige context nodig heeft.

```yaml
# claude_code_config.yaml
mcpServers:
  headroom:
    command: uvx
    args: ["headroom-mcp"]
    env:
      HEADROOM_CCR: "true"
```

Bijzonder relevant bij Orion-sessies die grote codebase-scans uitvoeren: `headroom_stats` geeft live inzicht in token-besparingen per sessie, zodat je precies ziet waar de meeste compressie plaatsvindt en waar niet.

## Hermes/Open Source Models — Hermes Agent: skills schrijven en zichzelf verbeteren

Nous Research's Hermes Agent is een open-source agentic framework dat 24/7 draait op NVIDIA RTX/DGX Spark hardware en zijn eigen skills schrijft, test en verfijnt. Deze week #2 trending op GitHub (190K+ stars), #1 meest gebruikte agent op OpenRouter.

De kern: Hermes functioneert als persistente orchestratielaag met een groeiende bibliotheek van Python-functies als skills. De loop die het systeem autonoom uitvoert:

1. Schrijf een skill voor een nieuwe taak
2. Test de skill op echte input
3. Verfijn op basis van uitkomst en foutmeldingen
4. Hergebruik bij vergelijkbare taken in de toekomst

```python
@skill(name="summarize_github_diff", version="1.2")
def summarize_github_diff(diff: str, context: str) -> str:
    """Auto-generated by Hermes Agent after 3 prior diff analyses."""
    ...
```

Het model achter Hermes is **Qwen 3.6 27B/35B** — een generatiesprong: deze modellen overtreffen vorige-generatie 120B/400B modellen op agentic benchmarks. Op DGX Spark (128GB unified memory, 1 petaFLOP) draaien ook 120B MoE-modellen continu zonder memory-bottleneck.

Het skills-patroon zelf is bruikbaar buiten Hermes. Bij Orion-taken die herhaaldelijk vergelijkbare analyses uitvoeren — dezelfde soort diffs, dezelfde soort security-checks, dezelfde soort API-responses valideren — is het aanleggen van een geversioned skills-bibliotheek via schrijf → test → verfijn → hergebruik een patroon dat op elk agentic framework werkt. Qwen 3.6 27B lokaal op RTX hardware is een privacyvriendelijke, kostenloze basis voor agent development waarbij je niet wilt dat code of data de omgeving verlaat.

## Tot slot

MCP wordt stateless op 28 juli. Ultracode, Headroom en Hermes zijn keuzes die je kunt faseren. De MCP-migratie niet. De vraag is of je de audit nu doet terwijl er nog zes weken zijn, of wacht totdat de finale spec live gaat en de tijdsdruk hoger is.
