De week sluit af met drie parallelle verschuivingen: model-transities bij de grote labs, een open-source release die lokale agentic setups democratiseert, en een developer-perspectief op proactieve modellen dat vraagt om system prompt-audits.

Opvallend is hoe snel het veld segmenteert: frontier reasoning modellen (Fable 5, GPT-o5), werkpaardmodellen die de agentic bulk doen (GPT-5.5 Instant, Gemini 3.5 Flash), en open-weight modellen die steeds dichter bij de cloudalternatieven komen (Gemma 4 12B). De grenzen tussen die lagen verschuiven maandelijks.

## OpenAI — GPT-5.2 geretireerd, GPT-5.5 Instant de nieuwe ChatGPT-default

Vanaf 12 juni 2026 zijn de GPT-5.2-modellen (Instant, Thinking, Pro) uit ChatGPT verwijderd. Bestaande conversations schakelen automatisch over naar GPT-5.5-equivalenten. GPT-5.5 Instant — gelanceerd op 5 mei — is nu de standaard voor alle ChatGPT-gebruikers.

De kwaliteitssprong is meetbaar: AIME 2025 score 81.2 (vs GPT-5.3 Instant), MMMU-Pro 76 (vs 69.2), en 52,5% minder gehallucineerde claims op high-stakes prompts in recht, geneeskunde en financiën. De search-tool heeft nu toegang tot past conversations, files en Gmail voor Plus/Pro-gebruikers via web.

Voor API-gebruikers is de urgentie concreet: wie nog `gpt-5.2-*` aanroept moet migreren naar `gpt-5.5-instant` of `gpt-5.5`. GPT-4.5 heeft een aparte sunset-deadline van **27 juni 2026** — een 30-daagse deprecation period die nu bijna afloopt.

```bash
# Controleer welke model-IDs je aanroept in productie:
grep -r "gpt-5\.2\|gpt-4\.5" ./src --include="*.py" --include="*.ts"
# Migreer naar gpt-5.5-instant voor bulk-tasks
# Gebruik gpt-5.5 voor reasoning-intensieve tasks
```

De hallucinatieverbetering bij 5.5 Instant is relevant voor verificatiestappen in RAG-pipelines: overweeg het als goedkopere verificatiestap vóór een dure reasoning call in fact-checking agents.

## Gemini — 3.5 Flash naar GA: frontier agentic performance bij flash-snelheid

Google bracht Gemini 3.5 Flash op 19 mei naar GA via Gemini API, AI Studio en Vertex AI. Het model overtreft Gemini 3.1 Pro op agentic benchmarks bij ~280 tokens/seconde output en significant lagere kosten ($1,50/1M input vs de Pro-prijs).

De benchmarks zijn concreet voor tool-use werklasten: Terminal-Bench 2.1 scoort 76,2% (vs 70,3% voor 3.1 Pro), MCP Atlas tool-use evaluatie 83,6%, en GDPval-AA agentic Elo 1656. Dynamic thinking is standaard aan — het model beslist zelfstandig wanneer het diep nadenkt.

```yaml
# Vertex AI deployment — Gemini 3.5 Flash
model: gemini-3.5-flash
thinking:
  enabled: true          # dynamic thinking standaard aan
context_window: 1048576
max_output_tokens: 65536
pricing:
  input_per_1m: 1.50
  cached_input_per_1m: 0.15   # 90% korting op gecachede tokens
```

De 90% cache-korting maakt grote-documentworkflows concreet: verwerk een hele codebase als context en betaal $0.15/1M op hergebruikte tokens. Voor MCP-gebaseerde agentic subagents is 3.5 Flash nu het meest kostenefficiënte alternatief met frontier tool-use kwaliteit.

Opgelet: deprecated per 25 juni 2026 zijn `gemini-3.1-flash-image-preview` en `gemini-3-pro-image-preview`. Controleer je model-ID's voor de deadline.

## Open Source Models — Gemma 4 12B: Apache 2.0, multimodaal en tool-calling op 16GB RAM

Google lanceerde Gemma 4 12B op 3 juni onder Apache 2.0. Het combineert vision (images + video, variabele resolutie, sterk in OCR en chart understanding), native function-calling en JSON structured output — en draait op 16GB VRAM of CPU-RAM.

Technisch cruciaal: de tool-calling interface is **Gemini API-compatibel**. Bestaande MCP- en function-calling setups werken direct zonder aanpassingen.

```python
# Tool-definitie werkt identiek op Gemma 4 12B als op Gemini 3.5 Flash
tools = [{
    "name": "search_codebase",
    "description": "Doorzoek de lokale codebase",
    "input_schema": {
        "type": "object",
        "properties": {
            "query": {"type": "string"},
            "file_pattern": {"type": "string"}
        },
        "required": ["query"]
    }
}]
# Drop-in vervanging voor cloud Gemini calls in bestaande MCP-setups
```

De Apache 2.0 licentie maakt fine-tuning en redistributie vrij — relevante combinatie voor GDPR-gevoelige workloads waarbij data de eigen infrastructuur niet mag verlaten. Een gespecialiseerde code-review agent, fine-getuned op eigen codebase, is nu realistisch op consumer-hardware.

## Open Source Tools — Microsoft Agent Framework BUILD 2026: Agent Harness en CodeAct

Op BUILD 2026 (2-3 juni) kondigde Microsoft drie productie-gerichte upgrades aan voor het Microsoft Agent Framework (MAF, 1.0 GA april 2026 — combineert AutoGen + Semantic Kernel):

**Agent Harness** voegt instruction merging, todo tracking en context compaction toe als first-class features. Dit reduceert token-verspilling in lange agentic runs: de harness bewaakt actief de context en comprimeert historiek op configureerbare drempels.

**CodeAct via Hyperlight micro-VM's**: model-gegenereerde code draait in hardware-geïsoleerde VM's die losstaan van de host-omgeving. Meerdere tool-calls worden gecollapst naar minder model-turns, wat zowel latency als kosten drukt.

**Hosted Agents in Foundry Agent Service** — GA eind juni — biedt session persistence, auto-scaling en ingebouwde observability als managed service.

```yaml
# MAF Agent Harness configuratie (Python SDK)
agent:
  harness:
    context_compaction:
      threshold_tokens: 80000
      strategy: "summarize_oldest"
    instruction_merging: true
    todo_tracking: true
  code_act:
    executor: "hyperlight"       # hardware-geïsoleerde micro-VM
    collapse_tool_calls: true    # meerdere tool-calls → minder model-turns
```

De Agent Harness context compaction is direct toepasbaar als patroon buiten MAF: structureer system prompts met expliciete compressie-instructies voor lange Claude Code sessies. CodeAct in Hyperlight convergeert met Simon Willison's MicroPython WASM sandbox — twee onafhankelijke oplossingen voor hetzelfde isolatieprobleem.

## AI Builders — Simon Willison: MicroPython WASM sandbox en Fable 5-proactiviteit

Simon Willison publiceerde op 6 juni zijn `micropython-wasm` alpha-package: Python-executie in een WebAssembly sandbox zonder filesystem-toegang, geen netwerk, deterministische uitvoer. Gebouwd als `datasette-agent-micropython` plugin voor veilige code-executie in agents.

```bash
# Installeer de datasette agent plugin
pip install datasette-agent-micropython

# Agent roept micropython_exec(code) aan → WASM sandbox
# Geen filesystem, geen netwerk, geen OS-calls mogelijk
# Deterministisch en volledig geïsoleerd van de host
```

Op 9 juni documenteerde hij zijn eerste indrukken van Claude Fable 5: het model neemt significant meer initiatief dan Opus 4.8 en handelt ambigue taken proactief af zonder te vragen. Zijn kwalificatie: *"relentlessly proactive"* — zowel kracht (minder micro-management) als risico (meer kans op ongewenste acties) voor agentic systemen.

De proactiviteitsshift vereist actie in bestaande setups. Zijn aanbeveling: audit system prompts en voeg expliciete negatieve instructies toe vóór migratie naar Fable 5.

```
# System prompt-toevoeging voor Fable 5-agents:
Vraag altijd expliciete bevestiging vóór je:
- bestanden aanmaakt of overschrijft buiten de opgegeven directory
- externe API-calls maakt die data wegschrijven
- meer dan één stap uitvoert zonder tussentijdse check bij de gebruiker
```

De MicroPython WASM benadering en Microsoft's Hyperlight zijn technisch complementair: WASM via browser-sandbox semantics, Hyperlight via hardware-VM. Voor Orion-agents die Python-snippets uitvoeren (data-transformaties, calculaties, CSV-analyse) is micropython-wasm een direct inzetbare sandbox zonder infrastructuuroverhead.

## Tot slot

Twee trends worden deze week zichtbaar: grote labs consolideren hun model-families (GPT-5.2 weg, Gemini 3.1 deprecated) terwijl open-weight modellen de capabiliteitskloof met cloud snel dichten. Gemma 4 12B draait met Gemini API-compatibele tool-calling op 16GB RAM — dat was zes maanden geleden nog frontier-territorium.

De vraag die blijft hangen: als lokale modellen dezelfde MCP tool-calling interfaces spreken als cloud modellen, op welk punt kies je nog bewust voor cloud in een privacy-kritieke pipeline?
