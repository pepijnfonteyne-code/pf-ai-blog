Twee maanden na de lancering van Claude Code on the web maakt Anthropic de volgende logische stap: niet alleen code schrijven in de cloud, maar code-agents *plannen* in de cloud. Claude Code Routines laat je prompts uitvoeren op een cron-schema, bij een GitHub-webhook of via een API-call — zonder dat je machine aan hoeft te staan, zonder eigen server, zonder zelf-gehostede cron-infrastructuur.

Tegelijk wordt de economie van agentic gebruik fundamenteel herzien: de impliciete subsidie op Agent SDK-gebruik via Pro/Max-subscriptions stopt per 15 juni. Wie zware agentic workflows draait, budgetteert nu anders. En in het open-source kamp introduceert Moonshot AI Kimi K2.7-Code — 1T parameters, 256K context, MIT-licentie, weights gewoon op HuggingFace.

## Claude Code — Routines: geplande agents in de cloud

Op 9 juni lanceerde Anthropic [Routines in Claude Code](https://claude.com/blog/introducing-routines-in-claude-code) — de feature waarmee je elke agent-prompt kunt plannen of triggeren vanuit externe events. Drie trigger-types:

- **Scheduled**: cron-achtige timing, ingesteld via de UI of API.
- **GitHub event**: trigger op push, PR-open, issue-comment — alles wat een GitHub webhook kan sturen.
- **API trigger**: eigen code belt de Routine-endpoint aan, bijvoorbeeld na een CI-run.

De uitvoering is asynchroon en serverless-gehost door Anthropic. Je sessie draait op Fable 5 (of Opus 4.8 als fallback), heeft volledige Claude Code-tooling beschikbaar en kan zelf git-commits aanmaken, PR's reviewen en bestanden aanpassen.

Het meest concrete use case: een Routine-prompt die elke nacht open PR's reviewt, tests runt en een samenvatting post in Slack. Je wacht 's ochtends op kant-en-klare feedback in plaats van handmatig te beginnen. De "wake up to PRs ready to merge"-workflow waar eerder tools als Devin op mikte, maar nu ingebakken in Claude Code en zonder eigen hostingkosten.

Beschikbaar voor Pro, Max, Team en Enterprise met Claude Code on the web ingeschakeld. API-triggers maken het ook integreerbaar in bestaande CI/CD-pipelines via een POST-call.

```yaml
# Voorbeeld GitHub-event trigger (conceptueel)
trigger:
  type: github_event
  events: [pull_request.opened, pull_request.synchronize]
  repo: pepijnfonteyne-code/orion
prompt: |
  Review deze PR voor correctheid, security en stijlconsistentie.
  Post een samenvatting als PR-review comment.
```

De interessantste vraag is wat dit doet met de grens tussen "tool" en "systeem". Een Routine die 's nachts werkt, resultaten wegschrijft en de volgende dag een andere Routine triggert via een API-call is conceptueel een multi-agent pipeline — gebouwd zonder eigen orchestration-laag.

## Claude Code — Agent SDK credit-split (15 juni)

Minder zichtbaar maar even impactvol: [vanaf 15 juni 2026](https://www.digitalapplied.com/blog/anthropic-claude-credit-overhaul-june-15-2026) telt `claude -p`-gebruik en Agent SDK-calls niet meer mee uit de Pro/Max/Team/Enterprise-abonnementspools.

Het nieuwe model:
- **Aparte credit-pool** voor Agent SDK en `claude -p`, ter grootte van het maandelijkse abonnementsbedrag in dollar.
- **Rate limits verdubbeld** als compensatie voor de lagere impliciete subsidie.
- **Na uitputting**: standaard API-tarieven, geen harde stop.

Voor lichte workflows — één of twee Agent SDK-calls per dag — verandert er weinig. Voor zware agentic setups (research-agents, nachtelijke PR-reviews, dagelijkse blog-pipelines) loopt het krediet sneller leeg dan de abonnementspools deden.

Praktische aanpak: monitor token-gebruik per Routine/Agent-run via AgentsView of eigen logging, cache zware context-payloads met prompt caching, en bepaal per workflow of het economischer is via directe API-calls of via de Claude Code-UI. De rate limit-verdubbeling compenseert enigszins de verhoogde kosten voor parallelle runs. [DevToolPicks](https://devtoolpicks.com/blog/anthropic-splits-claude-subscriptions-agent-sdk-credit-june-2026) heeft een uitgebreide breakdown per abonnementstype.

## Open Source Models — Kimi K2.7-Code: 1T params, 256K context, MIT

Moonshot AI publiceerde op 12 juni [Kimi K2.7-Code](https://cryptobriefing.com/kimi-k2-7-code-open-source-release/) — een Mixture-of-Experts model met 1 biljoen parameters totaal en 32B actief per token. Technische specs: 384 experts, 61 lagen, MLA-attention, 256K context-window, 400M MoonViT vision encoder voor beeld- en video-input. Weights op HuggingFace onder Modified MIT-licentie (commercieel gebruik toegestaan met attributie).

Benchmarkresultaten ten opzichte van K2.6:

| Benchmark | Delta |
|---|---|
| Kimi Code Bench v2 | +21.8% |
| Program Bench | +11.0% |
| MLS Bench Lite | +31.5% |
| Reasoning tokens | −30% |

De 256K context maakt het bruikbaar voor grote codebase-analyse — het soort taak dat normaal Opus of Fable 5 vraagt. API beschikbaar op $0.95/$4.00 per MTok (input/output), OpenAI- en Anthropic-compatible. [ExplainX AI](https://www.explainx.ai/blog/kimi-k2-7-code-open-source-coding-model-2026) heeft een gedetailleerde vergelijking met de concurrent open-source coding models.

Voor self-hosting is de rekensom aantrekkelijk: 32B actieve parameters passen op 2x A100-80GB bij 4-bit quantisatie. De MoE-architectuur geeft goede inference-snelheid bij relatief lage kosten per token, omdat de meeste experts per token niet geactiveerd worden.

## AI Builders — Simon Willison: datasette-agent 0.2a0 en AgentsView

Simon Willison bracht [datasette-agent 0.2a0](https://simonwillison.net/2026/Jun/10/datasette-agent/) uit met een patroon dat de moeite waard is om te kopiëren: de LLM-agent heeft een `save_query`-tool beschikbaar, maar elke aanroep vereist expliciete menselijke goedkeuring vóór uitvoering. Schrijfoperaties — persistente, moeilijk terug te draaien acties — gaan door een menselijke checkpoint.

Dit is een eenvoudige maar effectieve manier om agent-autonomie te begrenzen zonder de workflow te breken: lees-tools zijn volledig autonoom, schrijf-tools vragen bevestiging. Het patroon werkt precies andersom dan de meeste agent-frameworks die goedkeuring als optionele feature toevoegen. Hier is de default safe: de tool bestaat, de agent kan hem aanroepen, maar de uitvoering wacht op jou.

Direct toepasbaar als MCP-server-ontwerp: `list_*` en `get_*`-operaties vrij, `create_*` en `delete_*`-operaties via approval-callback. Datasette 1.0a33 breidt het `?_extra=` patroon ook uit naar queries en rows — interessant voor het bouwen van query-APIs die agents direct kunnen aanroepen.

Parallel gebruikt hij [AgentsView](https://simonwillison.net/2026/Jun/11/datasette/) voor lokale monitoring van token-verbruik over Claude Code, Cursor en andere coding agents per sessie. Nu Agent SDK-kosten apart gaan lopen, is weten welke workflows de meeste tokens kosten de eerste stap naar kostenbeheer — niet achteraf de factuur bekijken maar per sessie bijhouden.

## Tot slot

Routines is de feature die Claude Code omzet van een gereedschap in een systeem. De vraag die blijft hangen: op welk punt word je afhankelijker van Anthropic's cloud-infrastructuur dan van je eigen code? En is dat een probleem als de alternatieve infrastructuur — eigen cron-servers, agent runners, orchestration-lagen — toch al Anthropic's API aanbelt?
