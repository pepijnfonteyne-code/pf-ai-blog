De week sluit af met drie concrete tools die de manier waarop je werkt direct veranderen: Claude Code Agent View maakt tmux overbodig voor multi-agent monitoring, Gemini's Managed Agents API biedt een volledig gemanaged Linux-sandbox-model via één API-call, en DeepSeek R1-0528 bewijst opnieuw dat open-source reasoning op frontier-niveau beschikbaar is onder MIT. Daarboven neemt de MCP Extensions-laag vorm aan met een Tasks-API voor async agentic work.

Wat verbindt dit alles: de tooling voor meerdere gelijktijdige, autonome agents rijpt snel. Niet als concept, maar als concrete implementatie die je vandaag kunt testen.

## Claude Code — Agent View, Safe Mode en de /cd-command

Claude Code v2.1.139 (research preview, 11 mei 2026) introduceerde **Agent View**: één CLI-dashboard dat alle actieve sessies overzichtelijk samenbrengt. Start je meerdere parallelle agents — één per microservice, één per feature-branch, één als linting-runner — dan toont `claude agents` een tabeloverzicht met:

- sessienaam en laatste response
- timestamp en wachtstatus (actief / wacht op input / PR geopend)
- de mogelijkheid om direct inline te antwoorden of in te springen zonder nieuwe shell te spawnen

```bash
# Alle actieve Claude Code-sessies in één overzicht
claude agents
# → attach naar sessie, inline reply, of sluit sessie
# → geen context-verlies, geen extra terminal
```

Agent View vervangt tmux/meerdere terminaltabs volledig. Voor Orion-workflows met meerdere parallelle agents is dit de interface die ontbrak: in real-time zien wie blokkeert, wie klaar is, en wie input nodig heeft.

In combinatie met de **verdubbelde rate limits** (juni 2026) en de nieuwe **`/cd`-command** maakt dit multi-agent work practisch. De `/cd`-command verplaatst een sessie naar een andere working directory zonder de prompt-cache te herbouwen. Technisch: hij voegt de `CLAUDE.md` van de nieuwe directory toe als message en verplaatst project storage, zodat de volledige context behouden blijft:

```
/cd ~/projects/orion-backend
# CLAUDE.md van backend wordt als message ingevoegd
# prompt-cache intact — geen cold-start
```

Dit is ideaal voor monorepos: één sessie, meerdere sub-projecten, zonder cache-rebuild bij elke context-switch.

**Safe Mode** (ook juni 2026) blokkeert destructieve shell-commando's op protocol-niveau vóór uitvoering. Voor CI-pipelines of geautomatiseerde routines is dit een protocol-level guardrail — niet enkel een prompt-instructie. Een agent in Safe Mode kan geen `rm -rf`, geen force-push, geen database-drop uitvoeren, ongeacht wat de instructie zegt.

De combinatie Agent View + Safe Mode + `/cd` + verdubbelde rate limits is de sterkste Claude Code-upgrade dit kwartaal.

## Gemini — Managed Agents API in public preview

Google lanceerde tijdens I/O 2026 (19 mei) de **Managed Agents API** in public preview: één POST-call provisioned een Gemini 3.5 Flash-agent (model-ID: `antigravity-preview-05-2026`) in een geïsoleerde Linux-sandbox met code-execution, web search en URL fetch ingebakken.

```python
# Managed Agents API: één call, agent doet de rest
response = genai.interact(
    model="antigravity-preview-05-2026",
    prompt="Analyseer deze dataset en maak een visualisatie",
    tools=["code_execution", "web_search", "url_fetch"]
)
# Sandbox: stateful binnen sessie, ephemeral daarna
```

De architectuur is fully managed: geen orchestratielogica schrijven, geen tool-calling loop beheren, geen sandbox provisioneren. De Interactions API abstraheert de volledige agent-lifecycle — sandbox provisioning, tool-calling loop, resultaataggregatie — achter één endpoint.

Dit is Google's directe tegenhanger van Claude's computer-use en Anthropic's hosted agent-execution. Het onderscheidende punt: de sandbox draait een volledig Linux-environment, geschikt voor complexe data-pipelines of multi-file codegeneratie met directe uitvoering. Vergelijkbaar met Anthropic's computer-use, maar als fully-managed hosted service zonder eigen sandboxing-infrastructuur.

Aandachtspunten: pre-GA software, geen SLA, niet voor productie of gevoelige data. Maar als evaluatieplatform voor use-cases waar een volledig Linux-env nodig is, is de barrier to entry nul. Test latency en kosten versus eigen MCP-tool-orchestratie voor de juiste trade-off.

## Hermes/Open Source Models — DeepSeek R1-0528

DeepSeek R1-0528 (uitgebracht 28 mei) is een 671B-parameter Mixture-of-Experts model onder **MIT-licentie**, beschikbaar op Hugging Face. Het activeert 37B parameters per token via dynamic routing — wat de inferentiekosten beheersbaar houdt ondanks de totale parametercount.

AIME 2025-nauwkeurigheid: **87,5%** (was 70% bij de vorige versie). Dat overtreft GPT-4's AIME-score.

De distilled varianten zijn de praktische insteek:

| Variant | Parameters | Hardware |
|---|---|---|
| R1-0528-1.5B-distill | 1,5B | consumer CPU |
| R1-0528-32B-distill | 32B | één RTX 4090 |
| R1-0528-70B-distill | 70B | multi-GPU setup |

De 32B-distill draait op één RTX 4090 via supervised fine-tuning op R1-0528-outputs. MIT-licentie: commercieel gebruik en fine-tuning zonder restricties, geen attribution-verplichtingen buiten de licentietekst.

Gebruik dit als basis voor lokale agent-workloads waar privacy of latency vereist dat je niet naar een externe API wilt. Vergelijk reasoning-kwaliteit en cost-per-token met Claude Haiku 4.5 voor budget-gevoelige Orion-componenten.

Parallel verscheen Microsoft's **Phi-4 reasoning-vision** (14B): multimodaal, past op een laptop-GPU met 8 GB VRAM. Compact alternatief voor use-cases die beeld + tekst + redeneren combineren op edge-hardware.

## Open Source Tools — MCP Extensions: Tasks API en MCP Apps

Naast de stateless protocol-kern brengt de MCP 2026 roadmap een **Extensions-laag** met twee concrete toevoegingen: MCP Apps en de Tasks-extensie (SEP-1686).

**MCP Apps** zijn server-rendered UIs in de client. Een MCP-server kan een interface aanbieden die direct in de MCP-client rendert — geen apart frontend-project, geen browser-switch. Denk aan een monitoring-dashboard of configuratie-UI die volledig in Claude Code of een andere MCP-client draait.

**Tasks** is de extensie voor langlopend async werk:

```yaml
# Tasks-extensie configuratie
task:
  id: data-pipeline-run
  retry:
    max_attempts: 3
    backoff: exponential
  expiry:
    policy: ttl
    ttlMs: 3600000   # 1 uur TTL
```

Retry-semantics voor transient failures, expiry policies voor langlopende jobs, en async status-polling via de client. Dit vervangt de custom polling-logica die nu in agentic workflows zit die "wachten" op een extern systeem — elke workflow die nu via manual polling werkt, kan naar de Tasks-extensie gemigreerd worden.

Enterprise-features (audit trails, SSO-auth, gateway-standards) worden als Extensions geleverd, niet in de core. De core blijft minimaal en stateless; de Extensions-laag voegt domein-specifieke functionaliteit toe zonder het protocol te verzwaren.

De RC is gepland op 28 juli. Zorg dat zelfgebouwde MCP-servers stateless zijn vóór die datum.
