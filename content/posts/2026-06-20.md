Twee bewegingen tekenen vandaag de agentic stack. Aan de output-kant wordt agent-output voor het eerst first-class deelbaar: Claude Code Artifacts genereert live HTML-dashboards op een eigen URL, zonder dat je een frontend hoeft te bouwen. Aan de infrastructuurkant lost MCP Enterprise-Managed Authorization het grootste enterprise-blokkade op — herhaalde OAuth-prompts per server zijn verleden tijd.

Daarboven consolideert Google's Gemini CLI als serieuze open-source concurrent voor Claude Code, en Z.ai's GLM-5.2 geeft Hermes Agent een 1M-context backend bruikbaar voor grote codebase-taken. Vier updates, allemaal direct relevant voor wie nu met agentic workflows in productie gaat.

## Claude Code — Artifacts: live deelbare agent-output zonder frontend

De meest concrete Claude Code update van deze week is Artifacts voor Team- en Enterprise-abonnementen. Een lopende Claude Code sessie kan worden omgezet in een live, interactieve HTML-webpagina op een eigen URL. Meerdere databronnen en code worden ingebed in de output — de pagina is direct deelbaar via een browser-link, zonder dat de ontvanger een Claude-account nodig heeft.

Wat dit concreet betekent: als je Orion een analyse laat draaien over repo-data of externe APIs, kun je de output nu direct publiceren als een interactief dashboard voor stakeholders. Geen React-boilerplate, geen aparte frontend pipeline, geen export-naar-PDF stap. De Artifacts URL is live en kan meerdere databronnen embedden die parallel bijwerken.

Technisch gezien construeert de agent de UI als onderdeel van de task-output — custom HTML met ingebedde data-feeds. Voor Teams en Enterprise zijn Artifacts beschikbaar op een Anthropic-gehoste URL. De implementatie is bewust zonder build-stap: de agent schrijft de complete interactieve pagina als enkel artefact.

De toepassing voor Pepijn en Duncan is direct: rapportage vanuit agentic Orion-runs kan naar buiten zonder een aparte frontend te bouwen. Sprint-dashboards die automatisch refreshen vanuit een remote routine, of architectuur-analyses die een PM rechtstreeks in de browser bekijkt — beiden worden nu mogelijk zonder frontend-engineering overhead.

## MCP — Enterprise-Managed Authorization stabiel

Op 18 juni 2026 is de EMA-extensie voor MCP stabiel verklaard. Enterprise-Managed Authorization lost een concreet enterprise pain point op: in een team met tientallen MCP-servers (GitHub, Jira, Slack, databases) moest elke gebruiker zich per server opnieuw authenticeren via OAuth. EMA centraliseert dit.

De flow: een admin configureert OAuth-scopes en credential-stores eenmalig via de centrale IdP. Bij de eerste login van een teamlid krijgt die automatisch toegang tot alle geconfigureerde MCP-servers, zonder consent-scherm per server en zonder herhaalde re-auth bij token-expiry. Anthropic, Microsoft en Okta zijn al early adopters van de centrale provisioning flow.

```yaml
# Concept MCP EMA config (admin-side)
mcp_enterprise:
  identity_provider: "okta"
  managed_servers:
    - id: github-mcp
      scopes: ["repo:read", "issues:write"]
    - id: jira-mcp
      scopes: ["projects:read", "issues:write"]
  auto_provision: true
  token_refresh: "silent"
```

Technisch reist de autorisatie via EMA-metadata in het MCP-handshake-protocol. De server valideert via de centrale IdP-integratie; Tier 1 SDKs (TypeScript, Python) ondersteunen EMA al in de huidige stable release.

Voor enterprise Claude Code deployments — een team dat Orion-agents deelt met gecentraliseerde MCP-integraties — betekent dit eenmalige configuratie en frictionloos onboarden van nieuwe teamleden. Geen IT-ticket per developer voor elke tool-integratie.

## Open Source Tools — Gemini CLI: terminal agent met MCP-support

Google's Gemini CLI is inmiddels op 96.600+ GitHub-stars beland en positioneert zich als meest directe open-source concurrent voor Claude Code als terminal agent: Apache 2.0, volledige ReAct loop, 1 miljoen token context, ingebouwde MCP server support — gratis toegankelijk via een Google-account (Gemini 2.5 Pro).

Vier technische details die het waard zijn:

**GEMINI.md als context file.** Analoog aan CLAUDE.md leest Gemini CLI een `GEMINI.md` uit de repo-root als persistent context. Dit is het tweede major agentic tool dat dit patroon implementeert — industry-convergentie rond file-based agent context.

**Conversation checkpointing.** Sessies worden opgeslagen en hervat inclusief token-cache. Kritiek voor long-running agentic tasks zonder volledig opnieuw op te starten.

**Non-interactieve JSON output.** Via `--json` flag produceert Gemini CLI machine-readable output voor CI/CD pipelines — analoog aan `claude -p --output-format json`.

**Officiële GitHub Action.** Een eerste-party Action voor PR-review en issue triage, direct bruikbaar in bestaande CI-workflows.

MCP-servers worden geconfigureerd via `~/.gemini/settings.json` — hetzelfde patroon als Claude Code's MCP-config. Dit maakt hybride setups mogelijk: dezelfde MCP-servers aanroepen vanuit zowel Claude Code als Gemini CLI voor directe output-vergelijking. De gratis Gemini 2.5 Pro toegang maakt dat goedkoop te testen.

Voor Orion-architecturen is Gemini CLI bruikbaar als fallback of benchmark. Je kunt dezelfde MCP-toolset en GEMINI.md/CLAUDE.md structuur deployen op beide agents, en output vergelijken zonder twee infrastructuren te onderhouden.

## Hermes/Open Source Models — GLM-5.2 als Hermes-backend

Z.ai lanceerde GLM-5.2 op 13-14 juni: een open-weights model met 1M token context, 131.072 output tokens en twee selecteerbare thinking-effort niveaus. Nous Research integreerde GLM-5.2 binnen dagen als backend-optie in Hermes Agent — compatible met Claude Code, Cline, OpenCode en OpenClaw.

De twee thinking-effort niveaus zijn architectureel interessant voor gelaagde orchestratie:

```python
# Hermes Agent met GLM-5.2, selectieve thinking depth
client = HermesClient(
    model="glm-5.2",
    thinking_effort="light"   # goedkoop voor routing en planning
)

# Complexe subtaak: switch naar diepe modus
result = client.run(
    task=complex_code_task,
    thinking_effort="deep"    # volledige redenering voor code-generatie
)
```

De lichte modus is goedkoop genoeg voor routing en planning-stappen in een multi-agent pipeline; de diepe modus reserveer je voor complexe code-generatie of analyse. Dit maakt cost-optimized Orion-orchestraties mogelijk waarbij niet elke subtaak dezelfde compute nodig heeft.

De 131K output tokens zijn praktisch voor grote code-generatietaken waarbij je volledige bestanden of migratie-scripts in één response nodig hebt. Z.ai publiceerde bij launch geen benchmarks — bewuste positionering op practical use. De Hermes Agent integratie maakt het direct testbaar zonder zelf een inference-stack op te zetten.
