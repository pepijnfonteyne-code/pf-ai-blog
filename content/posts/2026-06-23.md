Twee architectuurverschuivingen domineren deze week: MCP laat sessie-state los en Claude Code verdubbelt qua capaciteit. Beide veranderen hoe je agentic pipelines bouwt en schaalt. Op de achtergrond: een Gemini API-breaking change die stilletjes kwaliteit afknijpt als je hem mist, en twee open-source modellen die het speelveld voor coding-agents verbreden.

De gemeenschappelijke draad is schaalbaar agentic werk — minder infrastructurele frictie, meer parallelle uitvoering, en meer controle over het risicoprofiel van autonome agents.

## MCP — Release Candidate: stateless core, Tasks en MCP Apps

De release candidate voor de volgende MCP-specificatie is beschikbaar. De grootste wijziging: de protocol-kern gaat stateless op standaard HTTP zonder sticky sessions.

Tot nu toe vereisten MCP-servers sessie-affinity op de load balancer — elke client-verbinding moest bij dezelfde instantie terechtkomen vanwege in-memory state. De nieuwe RC doorbreekt die aanname. Servers kunnen nu horizontaal schalen zoals elke stateless REST-service, zonder dat de load balancer verbindingen moet pinnen.

Wat de RC verder introduceert:

**Extensions-laag:**
- **Tasks**: retry-semantics en expiry-policies voor asynchrone agent-jobs. Relevant voor langlopende Orion-jobs die nu falen bij netwerk-timeouts.
- **MCP Apps**: servers kunnen server-rendered UI's pushen naar clients — embedded interfaces in agent-tools zonder aparte frontend-deployment.

**OAuth/OIDC-hardening**: autorisatie wordt formeel gespecificeerd, wat multi-tenant setups veiliger maakt.

**Breaking changes**: Tier 1 SDKs (Python, TypeScript) zijn verplicht compatibel binnen het 10-weekse validatievenster. Bestaande MCP-servers met stateful aannames (sessiebeheer, in-memory state) moeten gemigreerd worden. Finale spec gepland op 28 juli 2026.

Actie nu: screen je bestaande MCP-servers op `session_id`-afhankelijkheden en in-memory state. Alles wat per-verbinding state bijhoudt is een kandidaat voor migratie vóór de finale release.

## Claude Code — Sub-agent chains 5 niveaus diep, destructive blocks en 2× rate limits

Week 24 bracht een combinatie van capaciteitsuitbreiding en veiligheidsrails die samen het autonome gebruik herdefiniëren.

**Sub-agent chains**: agents kunnen nu zelf sub-agents spawnen tot 5 niveaus diep. De cap van 5 voorkomt runaway-recursie terwijl complexe orchestration mogelijk blijft. Dit opent het pad naar hiërarchische taakdecomposities waarbij een topniveau-agent werk delegeert aan gespecialiseerde sub-agents die zelf verdere parallellisatie doen.

**Destructive-command-blocks**: auto-mode blokkeert nu standaard een reeks git-commando's die moeilijk te reverteren zijn:

```bash
git reset --hard
git checkout -- .
git clean -fd
git stash drop
git commit --amend  # op sessie-externe commits
```

Ook IaC-destroy commando's zijn geblokkeerd tenzij expliciet gevraagd. Dit is de juiste default voor autonome pipelines — een agent die per ongeluk `git reset --hard` uitvoert op een productie-branch heeft geen tweede kans.

**Rate limits verdubbeld**: directe impact voor zwaardere agentic builds en CI-gebaseerde agent-pipelines. Minder throttling bij parallelle sub-agent uitvoering.

**`fallbackModel` uitgebreid**: accepteert nu tot drie modellen in volgorde. Dit maakt multi-model orchestration robuuster bij tijdelijke model-uitval of capaciteitsproblemen.

**`/cd` commando**: wisselt werkdirectory mid-sessie zonder de prompt-cache te verbreken. Handig voor multi-repository workflows binnen één sessie.

## Gemini — 3.5 Flash GA: thinking_level en Managed Agents in preview

Gemini 3.5 Flash is GA als snelste frontier-model voor agentic en coding tasks (4× sneller dan andere frontier-modellen). Managed Agents zijn in public preview: stateful agents draaien in geïsoleerde, Google-hosted Linux sandboxen.

De breaking change die stil binnenkwam: **`thinking_budget` is vervangen door `thinking_level`**.

```python
# Oud — werkt niet meer
response = model.generate_content(
    prompt,
    generation_config={"thinking_budget": 1024}
)

# Nieuw
response = model.generate_content(
    prompt,
    generation_config={"thinking_level": "medium"}
)
```

Wat je moet weten:
- Default is nu `medium` (was voorheen `high`) — stille kwaliteitsverslechtering bij een directe port zonder aanpassing.
- `thinking_level: low` is geoptimaliseerd voor code en tool-calling — sneller en goedkoper met vergelijkbare coding benchmark-scores.
- Function calling vereist nu een uniek `id` per call dat in de `functionResponse` terug moet komen.

Managed Agents bieden een alternatief voor zelf-gehoste sandboxen voor Orion-achtige systemen. Prijzen: $1,50/1M input tokens, $9/1M output tokens.

## Open Source Models — Hermes Agent v0.17.0 en GLM-5.2

Twee open-source releases deze week die het landschap voor agent-bouwers uitbreiden.

**Hermes Agent v0.17.0** (Nous Research, MIT, 200k stars): het onderscheidende is de ingebouwde skill-leerloop waarbij de agent skills creëert uit ervaring en ze verbetert tijdens gebruik. Subagent-parallelisatie en cron-scheduling zijn native ingebouwd. Ondersteunt 300+ modellen via OpenRouter/Nous Portal/OpenAI/Anthropic. De messaging-gateway bundelt Telegram, Discord, Slack, WhatsApp en Signal in één unified process. Het skill-leerloop-patroon is direct toepasbaar in Orion als zelf-verbeterende toolset.

**GLM-5.2** (Z.ai/Zhipu AI, MIT): 753B MoE-model (40B actief per token), 1M-token context, geoptimaliseerd voor long-horizon agentic software engineering. OpenAI-compatibele chat-completions endpoint maakt het een drop-in vervanging in Cline, Roo Code of Claude Code als alternatief backend:

```yaml
# Voorbeeld: GLM-5.2 als backend in een OpenAI-compatibele setup
model: glm-5-2
base_url: https://api.z.ai/v1
api_key: ${Z_AI_KEY}
context_length: 1048576  # 1M tokens
```

De 1M-token context maakt het bruikbaar voor grote codebases zonder chunking-logica. MIT-licentie elimineert commerciële restricties. Initieel via Coding Plan; standalone API en open weights volgen.

## Tot slot

De stateless MCP RC en de sub-agent chains in Claude Code wijzen in dezelfde richting: agentic werk schalen vereist dat je infrastructurele state elimineert, niet abstraheert. Wie nu bouwt met stateful aannames staat over vijf weken voor een migratieklus. De vraag is niet óf je migreert, maar of je dat proactief doet of reactief — en wat de kostprijs is van dat verschil.
